# 行为规范导读

本文概述主要契约。完整的规范条款、语法矩阵和验收编号请查阅[英文行为规范](/docs/specification)；中文导读不增加新的规范要求。

## 文档与源码

Markdown 字符串是规范文档值。Lexical 状态、DOM、菜单、选区和未提交草稿都是瞬时状态，不作为持久化格式。

源码保留应分别讨论未改动区域、编辑后的块、结构移动、换行规范化和不支持的语法。局部编辑在映射明确时保留其他区域的空白与拼写，不能因此承诺所有输入都逐字节往返。

## 语法配置

默认 Eidos 配置与实验性 Obsidian 配置各自定义语法解释。标准 Markdown、GFM 和扩展语法的支持程度必须有明确标签。不能因为解析器识别了一种结构，就推断它已支持可视编辑或完整交互。

不支持的内容应保留原文或使用范围尽可能小的源码回退，不能静默删除。

## 选区与块操作

正文中可以跨块选择文本；正文外的留白可发起块框选。两类选区互斥，滚动不应让已选的屏幕外内容丢失。

拖动目标属于实际操作的把手，不属于另一个块中的文本光标。文档属性和底部脚注具有固定边界，不能按普通块任意移动。

## 菜单与局部编辑

插入菜单可过滤并支持键盘导航。静止鼠标下因滚动触发的 hover 不应反复覆盖键盘选择。浮层应锚定当前编辑目标，避免移动正文布局。

源码和公式草稿应支持提交、取消、错误提示与撤销。IME 组合输入、文本输入框和浮层有自己的按键优先级。

## 宿主、资源与安全

宿主负责存储、图片持久化与跨文档导航。组件只处理受允许的资源与链接，不能因文档内容获得任意文件系统权限。

同文档定位在编辑器内完成，不触发宿主页面跳转。异步资源操作需尊重文档切换、只读状态和取消信号。

## 验收方式

需要分别验证源码往返、局部修改、撤销、键盘操作、鼠标操作、嵌入容器、多个实例、主题和长文档。DOM 模拟环境的测试不能代替真实浏览器的布局与滚动验证。
