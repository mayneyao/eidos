# 规范索引

规范描述用户和宿主能够观察到的行为保证，不规定代码文件如何摆放。测试通过是实现证据；写入规范本身不意味着功能已经实现。

## 当前契约

- [编辑器行为规范](/docs/specification)：编辑、选区、撤销、源码编辑、资源策略与插件契约。目前仍是从 Eidos 配置演进而来的工作草案，不能把 EFM 特有条款当作所有 Markdown 的通用规则。
- [Obsidian 兼容性](/docs/compatibility)：实验性语法配置的支持与部分支持状态，不是对 Obsidian 应用的兼容承诺。
- [行为规范中文导读](./specification.md)：理解主要边界；不是英文规范的完整译本。

## 文档职责

通用编辑器契约跨语法配置适用；具体语法拼写和解释由所选 grammar 或 profile 决定。CommonMark、GFM 使用上游规范，不在本项目重复定义。

实现细节属于 `architecture/` 或对应代码，不应写成另一套用户语义。中文文档提供说明，规范性行为以英文文档为准。

## 验收证据

每项功能分别需要解析、可视化编辑、序列化、未改动源码保留和交互测试。扩展插件还需禁用、移除及不支持源码的测试；宿主集成需覆盖独立容器和多编辑器实例。

[交付路线](./roadmap.md)记录尚未完成的拆分与验收工作，不代替现有规范。
