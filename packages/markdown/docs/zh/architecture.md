# 实现架构

架构文档说明实现组织和技术决策，不代替行为规范或公开 API。

## 依赖方向

宿主与文档站使用公开包入口。React 组装层消费插件注册表、交互与功能贡献；具体功能依赖核心契约，核心和通用交互不应反向依赖具体语法实现。

普通 React 使用者无需接触 Lexical。高级插件 API 显式暴露相关集成边界，而不是把 Lexical 状态当作宿主存储格式。

## 职责划分

| 层               | 责任                                       |
| ---------------- | ------------------------------------------ |
| 规范             | 定义可观察行为、源码保留和安全契约         |
| `core`           | 文档会话、分析结果和源码范围等中立契约     |
| `plugin-system`  | 编译不可变的插件贡献                       |
| `profile-system` | 选择一个 codec 及匹配的插件集              |
| `features`       | 按功能归属组织语法、节点、展示、行为和测试 |
| 通用交互         | 选区、菜单、历史、焦点和编辑生命周期       |
| 宿主             | 存储、导航、资源解析和容器集成             |

## 当前状态与目标

拆分还未完成：`markdown/efm-document.ts` 和 `nodes/efm-semantic-node.tsx` 仍集中多种语法；插入宿主也保留部分复杂表单。仅创建 `features` 目录不等于完成插件所有权。

CommonMark 与 GFM 已拥有描述符、插入工厂和标准编辑行为。其他共享依赖仍需移出，才能宣称实现了完整的可扩展架构。

## 源码映射

当前保真机制结合源码范围提交与规范化文本对齐。重复内容、结构移动等场景的稳定映射仍需要更多证据，不能承诺无限制的逐字节往返。

## 测试与分发

测试与对应模块放在一起，兼容性样例和性能基准属于包。站点生产构建通过公开包入口消费产物，不通过源码别名绕过分发边界；开发服务器可使用别名实现热更新。

独立消费测试在工作区外安装 tarball，以严格 TypeScript 配置检查公开声明，并验证消费者自定义语法和 React 应用构建。
