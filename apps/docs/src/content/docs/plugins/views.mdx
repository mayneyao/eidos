## Declare a view

### File templates and dashboards

In Lite plugin API 3.2, `fileTemplates` adds entries to **New File**. Each entry
declares `id`, `title`, `extension`, `view`, and static UTF-8 `content` (up to
256 KiB). The referenced document View must have a matching `file/open`
placement. The host creates the file without overwriting and opens that View.

To compose existing content, a file View with `workspace.files.read` can use
the optional `ctx.capabilities.ui.resources` interface:

```ts
const resources = ctx.capabilities.ui.resources
if (!resources) throw new Error("Resource composition is unavailable")
const views = await resources.listViews("./downloads.eidos")
const view = views.find((item) => item.kind !== "file")
if (!view) throw new Error("No saved views")
const panel = await resources.mount(container, {
  kind: "eidos-view",
  path: "./downloads.eidos",
  tableId: view.tableId,
  viewId: view.viewId,
})
ctx.subscriptions.add(panel)
```

Use `{ kind: "file", path: "./notes.md" }` for text, Markdown or image previews.
For ordinary files such as GPX, `listViews(path)` returns matching enabled plugin
Views and the built-in preview as `{ kind: "file", editor, name, type }`.
Pass the chosen `editor` with the file source to retain the selected View.
Paths resolve from the dashboard file and remain inside its Space. Panels are
read-only, limited to 12, and cannot contain nested dashboards. `panel.refresh()`
reloads the reference. Embedded plugin Views receive
`ctx.presentation?.mode === "embedded"` and can simplify their toolbar.
The host manages rendering and grants. The dashboard never receives child
plugin handles. Use ordinary rectangular containers without transforms or
overlapping controls. For a floating menu, use a native HTML `popover`. Lite
clips resource surfaces beneath the most recently opened popover without resizing
their content. This capability is currently available in Lite.
Set `pointer-events: none` on resource containers during layout editing to let
drag and resize gestures cross previews. Restore it to interact with charts.

Each entry in views requires id, title, entry, and kind. The kind property is page or file. Access options include `"read"` and `"write"`. The default mode is `"read"`.

File views declare data interfaces in capabilities: `document` for text editing, or a combination of `eidos/schema`, `eidos/table`, and `eidos/config`.
For direct file reads or media playback, use fs and omit capabilities.
Text and Eidos interfaces apply to different file formats and you cannot combine them.

Choose a placement. The navigation and plugin/settings placements open a page. The file/open placement opens a file by extension. The table/view placement opens a file view with eidos/table within a table.

In Lite, the sidebar footer shows Settings, Plugins, and up to three standalone pages from enabled plugins. Pages appear in their default order until the user changes it. With more than three pages, the **…** menu lists all pages and supports pinning and drag reordering. Up to three pinned pages receive a visible slot. Remaining slots follow the saved order. Lite saves pins and ordering locally per Space. Narrow sidebars show icons with name tooltips. Pages dedicated to `plugin/settings` or `sidebar/explorer` do not appear unless they also declare a `navigation` placement. Showing an entry does not load its page contents.

The field `requires.pluginApi` declares the required API. These examples use `"3.0.0"`. The `apiVersion` is `1`, while the plugin version identifies its releases.

Add an optional `description` to the manifest to explain what your plugin does.
Use a nonempty line of plain text, up to 1024 UTF-16 code units. Lite shows this
summary in plugin lists and details, including for locally installed packages.
If absent, Lite uses the marketplace description when available.

```json
"description": "Keep Markdown filenames and existing leading H1 headings in sync."
```

## Current file and page

Check binding.kind before accessing the binding. A page supplies route. A file supplies file metadata and can describe a table location.

```ts
if (ctx.binding.kind === "page") {
  root.textContent = ctx.binding.route
} else {
  root.textContent = ctx.binding.file.name ?? "File"
}
```

FileRef members such as path, name, and size depend on the environment. Its id identifies the file within the current context. Use stable identifiers from your application data for persistent references.
