Import types from `@eidos.space/plugin-sdk` using `import type`. Eidos supplies the context when it calls mount or activate.

## Declare a view

Each entry in views requires id, title, entry and kind. kind is page or file; access is read or write and defaults to read.

File views declare their data interfaces in capabilities: `document` for text editing, or a combination of `eidos/schema`, `eidos/table` and `eidos/config` for file structure, the current table and plugin configuration. For direct file reads or media playback, use fs and omit capabilities. Text and Eidos interfaces apply to different file formats and cannot be combined.

Choose a placement: navigation and plugin/settings open a page; file/open opens a file by extension; table/view opens a file view with eidos/table within a table.

requires.pluginApi declares the required API; these examples use `"3.0.0"`. apiVersion is `1`, while the plugin's own version identifies its releases.

## Current file and page

Check binding.kind before accessing the binding. A page supplies route; a file supplies file metadata and can describe a table location.

```ts
if (ctx.binding.kind === "page") {
  root.textContent = ctx.binding.route
} else {
  root.textContent = ctx.binding.file.name ?? "File"
}
```

FileRef members such as path, name and size depend on the environment. Its id identifies the file within the current context; use stable identifiers from your application data for persistent references.

## Read and edit text

Declare `capabilities: ["document"]` and use ctx.capabilities.document. Writing also requires `access: "write"`.

| Method                            | Purpose                                           |
| --------------------------------- | ------------------------------------------------- |
| `read()`                          | Read a snapshot including text, version and dirty |
| `observe(listener, onError?)`     | Get an initial snapshot and subscribe to changes  |
| `edit({ text, expectedVersion })` | Update unsaved content; returns applied or stale  |
| `save()`                          | Save the file; returns saved or conflict          |
| `undo()` / `redo()`               | Undo or redo an edit and return a snapshot        |

This function body converts the current text to uppercase and saves it:

```ts
const document = ctx.capabilities.document
if (!document) throw new Error("Document capability required")
const current = await document.read()
const result = await document.edit({
  text: current.text.toUpperCase(),
  expectedVersion: current.version,
})
if (result.status === "stale") {
  await ctx.capabilities.ui.notify(
    "The text changed. Review it before editing again."
  )
  return
}
const saved = await document.save()
if (saved.status === "conflict") {
  await ctx.capabilities.ui.notify(
    "The file changed on disk. Your draft is still available."
  )
}
```

Use the version from the read snapshot as expectedVersion. On stale, preserve user input and let the user review newer content. On conflict, preserve the draft and explain the disk change. An editor handling continuous input should serialize edit calls so several requests do not use the same old version.

## Read files and play media

Lite's ctx.capabilities.fs provides readText/writeText, readBinary/writeBinary, list/stat, delete/rename, getUrl and watch. Text reads are limited to 2 MiB and binary I/O to 16 MiB. For larger media, play the streaming URL returned by getUrl.

```ts
const fs = ctx.capabilities.fs
if (!fs) throw new Error("Filesystem access is required")
const video = document.createElement("video")
video.controls = true
video.src = await fs.getUrl()
root.append(video)
```

File-view access is confined to the bound file and its allowed directory scope. Access throughout a Space requires workspace.files. Writes also require write access on the contribution. Direct writes, deletes and renames return BUSY for paths with an existing working copy; use the document interface for text editing, saving and conflict handling.

## Work with Eidos files

`ctx.capabilities.eidos` contains the `schema`, `table` and `config` interfaces you declare. For example, a table view that reads file structure and saves plugin configuration can declare:

```json
{
  "id": "board",
  "title": "Board",
  "kind": "file",
  "entry": "./src/board.ts",
  "capabilities": ["eidos/schema", "eidos/table", "eidos/config"],
  "access": "write"
}
```

Add a `table/view` placement for this view. Each declaration provides its corresponding interface; declaration order does not affect behavior.

### Browse file structure

Declare `eidos/schema`. Use `ctx.capabilities.eidos.schema.listTables()` to list tables in the file and `readTable(tableId)` to read fields. A file browser opens through a `file/open` placement matching `.eidos`; a table view can also read the structure of its containing file.

### Query the current table

Declare `eidos/table` and open through `table/view`. `ctx.capabilities.eidos.table` provides readContext for current schema and view information, readRows for records, aggregate for summaries, setViewConfig to replace the current view’s plugin configuration, openRecord for record navigation and watch for invalidation notifications. Read schema first and query using field IDs; these operations always target the bound table.

### Save plugin configuration

Declare `eidos/config`. Use read, write and watch on `ctx.capabilities.eidos.config` to access your plugin's configuration stored in the file. A file browser can select tables within that file; a table view uses its bound table ID.

```ts
const { table, config } = ctx.capabilities.eidos ?? {}
if (!table || !config) throw new Error("Table and config capabilities required")
const current = await config.read(table.tableId)
await config.write(table.tableId, {
  value: { ...current.value, compact: true },
  expectedVersion: current.version,
})
```

Writes require `access: "write"` and the version from the read result. If the version is stale, reread and reconcile the changes before writing. `config.watch(tableId, listener)` returns a subscription without an initial value; read initially and reread on notification. Notifications may include unrelated changes and stop after disposal.

Lite supports all three interfaces. CLI Serve provides `eidos/table`; declare only supported capabilities and verify with `check --target cli` when targeting Serve.

## Settings, storage and notifications

Lite views read settings with capabilities.settings.get(key); ordinary actions can also set/reset them. capabilities.storage supplies list/read/write/delete for private binary objects addressed by key. Declare the quota in manifest.storage.maxBytes. Private storage remains on the device.

capabilities.ui.notify(message) shows a notification. In environments supporting navigation, ui.openFile(relativePath) opens a file and ui.navigate(viewId, route?) opens a page. Check optional methods before calling them.

capabilities.network.read({ url }) makes bounded HTTPS requests to origins declared in browser.networkOrigins. For credentialed requests, use `isConfigured(connectionId)` and `request({ connection, body })` on `ctx.capabilities.connections` with a declared connection. Connections are available to pages, file views and ordinary actions. Users configure details and secrets in Eidos; action requests are cancelled when the invocation ends.

## Register commands and formatters

In activate, call capabilities.actions.register(id, handler) for a declared action. Its handler receives a context and performs operations through capabilities.

Register formatters with capabilities.formatters.register(id, provider). provider.format receives `{ text, path, signal }` and returns `{ text }`; Eidos applies an undoable edit.

## Process table records in batches

Register a table action with capabilities.actions.registerTableProvider(id, provider). getItems receives capabilities.eidos.table, read-only capabilities.eidos.config and signal and returns menu items. run also receives capabilities.target, task and connections.

target.count is the number of records in this run. Read them with target.readRows and pass each returned readToken to target.update. Before writing, submit a real output sample to task.declareOutputs and await validation; this establishes the fields the run may update. Report progress with task.report and check signal between batches. Cancellation retains completed changes.

## Release resources and handle errors

Add subscriptions to ctx.subscriptions, cancel asynchronous work with ctx.signal, and release interface resources in the dispose object returned from mount.

Common errors include PERMISSION_DENIED (insufficient access), INSTANCE_CLOSED (closed context), STALE_REVISION (changed data), BUSY (a managed resource), TOO_LARGE (a size limit) and TIMEOUT. Explain the failure to the user and preserve unsaved input.

See the [SDK types](https://github.com/mayneyao/eidos/blob/dev/packages/plugin-sdk/src/index.ts) for full signatures and the [plugin specification](https://github.com/mayneyao/eidos/blob/dev/docs/specs/eidos-lite-plugins-1.0.md) for behavioral requirements.
