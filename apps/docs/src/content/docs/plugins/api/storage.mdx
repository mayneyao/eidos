Declare storage.maxBytes. Binary objects are private to the plugin and local to the device, persisting across View and app restarts. read returns null for an absent key. Writes are subject to the declared quota and host limits. Lite API 3.11 adds opt-in storage.atomic: true for readVersioned and compareAndWrite. These compare and replace current object bytes atomically across owner windows; conflicts do not write. Re-read and replay the specific edit, not a stale full snapshot.

Usage guide: [services](/plugins/services/). [API index](/plugins/api/).

Signatures, parameters and return types are generated from the SDK. Optional members are not available in every host and context.

### PluginStorage.readVersioned

Supported hosts: <Badge text="Lite" variant="note" />

Lite API 3.11; requires storage.atomic: true. Read bytes and their opaque current-bytes token together. Both are null for an absent key; an empty stored object has a non-null token. Tokens are stable for identical bytes, not monotonic revision numbers.

### PluginStorage.compareAndWrite

Supported hosts: <Badge text="Lite" variant="note" />

Lite API 3.11; requires storage.atomic: true. Compare expectedVersion with the current token and replace bytes in one host operation. A conflict returns applied: false and the current token without writing. Reread and replay the specific edit before retrying. The 4 MiB object limit and declared plugin quota still apply.


```ts
compareAndWrite?(key: string, expectedVersion: string | null, data: Uint8Array): Promise<StorageWriteResult>;
```

| Parameter | Type | Required |
| --- | --- | --- |
| `key` | `string` | Yes |
| `expectedVersion` | `string &#124; null` | Yes |
| `data` | `Uint8Array` | Yes |

Returns: `Promise<StorageWriteResult>`.
