Versions records local snapshots of your Space. Use it to review earlier
work or restore a recorded state. It does not require an account.

## Enable history

Open **Versions** in Eidos Lite and choose **Enable versioning**.
The initial version records the Space's starting state.
Use **Changes** to review current work and **History** to browse saved versions.

## Save a milestone

1. Open **Changes**.
2. Review the added, modified, and deleted files.
3. Enter a version note, such as **Reading list before cleanup**.
4. Choose **Save version**.

**Check:** the new note appears in History.

## Inspect a version

Open **History**, select a version, and choose a file to inspect its changes.
Browsing history does not modify your current files.

## Restore deliberately

1. Select the target version in History.
2. Review the state you intend to restore.
3. Choose **Restore this version**.
4. Read the confirmation and confirm **Restore Space**.

This operation affects the Space, not just the selected file.
After restoring, open important files and check their contents.
Keep an independent backup for recovery after device or disk loss.

## Leave temporary files out

Use `.gitignore` or `.graftignore` in the Space root to exclude temporary
content from version tracking. For example:

```text
node_modules/
*.tmp
cache/
```

Excluded files cannot be recovered from a version that never captured them.
Physical file attributes used by File Metadata Management also require
separate backup verification. See [data safety](/user-guide/data-safety/).
