Versions records local snapshots of your Space.
Use it to review earlier work or restore a recorded state.
It works offline and does not require an account.

## Enable history

Open **Versions** in Eidos Lite.
Select **Enable versioning**.
The initial version records the current state of your Space.
Use **Changes** to review working edits.
Use **History** to browse saved versions.

## Save a milestone

1. Open **Changes**.
2. Review added, changed, and deleted files.
3. Enter a version note, such as **Reading list before cleanup**.
4. Select **Save version**.

**Check:** The new note appears in History.

## Inspect a version

Open **History**.
Select a version, then select a file to inspect its diffs.
Browsing history does not change your current files.

## Restore a previous state

1. Select the target version in History.
2. Review the file changes you plan to restore.
3. Select **Restore this version**.
4. Read the modal prompt and select **Restore Space**.

This operation restores the whole Space, not only the selected file.
After restoring, open important files and check their contents.
Keep an independent backup for protection against drive failures.

## Exclude temporary files

Open **Versions** and select **Build ignore rules** before enabling versioning
for the first time. The builder writes `.graftignore` or `.gitignore` in the
Space root. Both files use one pattern per line, and either can exclude files
from tracking:

```text
node_modules/
*.tmp
cache/
```

The builder combines rule templates, per-file exclusions for large files, and a
raw editor for both files. Templates cover videos, Node and build output, design
files, archives, system files and temporary files. Review the generated rules,
save once, then create the first version.

History cannot restore files that you excluded from tracking.
File attributes used by File Metadata Management require separate backup tools.
See [data safety](/user-guide/data-safety/).
