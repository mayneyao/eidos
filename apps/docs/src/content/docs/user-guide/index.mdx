Eidos stores structured data in portable `.eidos` files. This guide follows
the work you do with those files: design a table, enter and connect records,
build useful views, move data in and out, and keep the result safe.

The editing model is shared by the Web Editor, CLI Serve, and Eidos Lite.
Host-specific differences—such as where files are saved, whether attachments
can be acquired, and whether local history or Sync is available—are called out
where they matter.

## Pick the right starting point

- New to the data model? Start with [Eidos File basics](/user-guide/eidos-file-basics/).
- Designing a database? Go to [Tables and fields](/user-guide/tables-and-fields/).
- Looking for rows or building a workflow? Use [Views and querying](/user-guide/views-and-querying/).
- Unsure whether a change is durable? Read [Data location and safety](/user-guide/data-safety/).
- Connecting more than one device? Read [History, recovery, and Sync](/user-guide/history-and-sync/)
  before enabling Sync.

Your canonical data is stored in the `.eidos` file. An application may keep a
temporary working or recovery copy while you edit, so always understand the
current Host's save state before closing the file.
