**Manage files like a table, with custom fields, filters, and sorting.**
File Metadata Management is a Spark advanced feature. Spark is a one-time purchase, independent of subscriptions.

## Open file management

Right-click a folder in the Space Explorer and choose **Manage files**.
To manage the entire Space, use **Manage files** beside the Space heading, or right-click the heading and choose **Manage files**.
When the Explorer is showing a subfolder, the heading action manages that folder.

Eidos creates `.eidos/files.eidos` in the Space on first use and reuses it afterward.
Every folder opens this same configuration. The private `.eidos` folder stays out of the Explorer, file search, and the catalog's scan results.
Ordinary **New File** creates an independent document.

## Folder scope and shared views

The Space root shows all managed files. A folder shows its files and all descendants.
The breadcrumb in the window title bar shows the current scope; select an ancestor to expand it.
Back, forward, and refresh retain the folder scope in the page address.

Fields, field options, and saved views are shared across the Space.
Add a Status, Rating, or Tags field and edit cells as you would in a table.
Use Search, Filter, Sort, and Fields to organize the view.

The folder scope is combined with the selected view's filters.
Switching folders does not rewrite those saved filters or create another view.
For example, a view filtered to Status = Ready still shows only Ready files when opened from another folder.

## Open and preview files

The read-only `file` cell opens the physical file in your system viewer.
Choose **Open in sidebar** from a row menu to keep the table visible while previewing the file on the right.
Previews use your configured opening method, including custom File Views.
Local large files open without loading all content bytes into the editor; image thumbnails retain size limits.

The table refreshes after filesystem change notifications.
Scanning does not follow symbolic links and excludes the native scanner's ignored directories, including `.graft` and `.eidos`.

## Configuration and physical attributes

`.eidos/files.eidos` stores field definitions, options, and views.
Custom values live in the physical files' attributes: extended attributes on macOS and Linux, alternate data streams on Windows.
Editing a custom cell changes attributes, not the file's content bytes.
Copying the configuration alone does not copy your tags.

New custom fields use their exact names as storage keys.
Metadata fields cannot be renamed; existing generated storage keys retain their mapping.
Tables using the same namespace and storage key read the same physical attribute.

- Clearing a cell clears that attribute on one file.
- Deleting a custom field clears that attribute from files in the table's full scan scope. A folder filter does not limit schema changes. This can affect other configurations sharing the key.
- Renaming on the same filesystem can preserve attributes. Cross-drive copies, backup tools, and other transfer methods depend on filesystem and tool support.
- Content history or successful content synchronization does not prove that attributes were preserved. Verify attribute preservation separately for your backup, recovery, or transfer workflow.
- Attribute rollback uses an in-memory journal. It does not provide crash atomicity or protection from concurrent edits by other programs.

## Existing configurations

Existing metadata `.eidos` files remain directly usable.
Opening Space file management does not move, merge, or delete them, or import their field definitions and views.
If they share the global catalog's namespace and storage keys, they can still observe the same physical attributes.

## Built-in fields

System fields are read-only: `name`, `path`, `extension`, `size`, `mimetype`, `file`, creation time, and modification time.
In the Space catalog, `path` is relative to the Space root.
The filesystem-backed `files` table does not support inserting or deleting physical files through ordinary row operations, or serving as a Relation source or target.
