## Set properties directly

Right-click a file or folder in Eidos Lite and choose **Properties**.
You can also select an item and press **Alt + Enter**.

The property sidebar offers Tags, Rating, and Status:

- Open Tags to choose options. With no configured options, type a tag and press **Enter** to add it.
- Enter a rating and press **Enter**, or leave the field, to save it.
- Choose a status to save it immediately.
- Use the clear button beside a property to remove its value.

The sidebar uses the same property editors as table records, including colored Select and Tags options.
Text and number edits save when you leave the field. Failed edits offer **Retry** and **Discard change**.

Select multiple items in the file sidebar, then choose **Properties** to edit them together.
A property with different values shows **Mixed values**.
Applying a value sets that property on every selected item and preserves other properties.
If some items cannot be written, the sidebar lists their paths and errors.
A batch is a series of individual writes, so successful writes remain saved.

Folder properties belong to the folder itself.
They do not apply automatically to its children, including files created later.

## Define a custom property

Choose **Add property** in the property sidebar.
Enter its name and select Text, Number, Rating, Checkbox, Select, or Tags.
For Select or Tags, enter options separated by commas.

Definitions are shared across the entire Space.
The pencil button beside a property edits its definition, including Select and Tags options.
An existing property keeps its name and type.
Definitions are saved as fields in one `files.eidos` at the Space root.
Adding a custom property creates this file if needed; Tags, Rating, and Status can be set directly before it exists.
The sidebar and table editor use the same field definitions and physical attribute values.
Option changes that affect existing values must be reviewed in the table editor.

Property values are stored on each physical file or folder in the `space.eidos.meta` namespace.
Copying `files.eidos` alone does not copy property values.

## Manage a folder's properties

Right-click a folder and choose **Manage folder properties**, or use that button in the folder's property sidebar.
Eidos Lite opens a folder properties view with the shared Grid and Gallery interface, showing only that folder's descendants, including nested folders and empty folders.
It creates the root catalog on first use and never creates a catalog inside the selected folder.

Use Search, Filter, Sort, and Fields to organize the items and edit their properties.
Choose **Open in sidebar** from an item's row menu to keep the table visible while viewing its file on the right. The file uses your configured opening method, including custom File Views.

In Eidos Lite, hold **Option** on macOS or **Alt** on Windows/Linux while the row menu is open to reveal drag handles. Drag actions into your preferred order, or choose **Restore default order**. The order is saved in your local app preferences and applies across tables. Drag the file preview's title bar to move the desktop window.
The title shows a breadcrumb such as **Space › Projects › Properties**.
Choose an ancestor folder to manage its descendants, or the Space name to manage the entire Space.
The scope, active View, and open record are retained through refresh and back/forward navigation. The scope is not written into saved Views.
Saved filters combine with the folder scope.

Choose **Manage file properties** beside Search in the file sidebar to manage the current folder, or the whole Space when at the root.
Opening `files.eidos` directly shows the entire Space.
An unrelated file already using that name is never overwritten.

## Storage and file safety

Editing properties changes attributes, preserving file content bytes.
Symbolic links and paths outside the Space are rejected.
Native writes reject files with multiple hard links on Unix.
The filesystem must support the native attribute storage: extended attributes on macOS and Linux, or alternate data streams on Windows.

Renaming on the same filesystem usually preserves attributes.
Copies, backups, and transfers depend on the tools and filesystem involved.
Use tools that preserve attributes when these values matter.

## Advanced: SQL and custom Views

The shared `files.eidos` is a standard Eidos File with Grid, Gallery, and custom Views.
Use its SQL interface for advanced queries. Folder scope applies to the editor's data queries; SQL queries use their own explicit conditions.

Existing file metadata indexes remain usable without migrating their values.
Indexes read the same physical attributes when they use the same namespace and storage key.

Editing an index column writes its attribute on the physical file or folder.
Clearing a cell removes that value.
Deleting a custom column clears that attribute on items in the index, which also affects other readers using the same namespace and key.

Directories appear as rows, including empty folders.
The read-only `is_dir` Checkbox is checked for folders and unchecked for files. Filter it to show only folders or only files.
Their `file` attachment is empty; folder size is the native directory entry size, not a recursive total.
Read-only fields such as name, path, extension, size, and modification time come from the filesystem.
