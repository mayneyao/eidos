## A Space or file will not open

Confirm that the folder is still in its original location and that your account can read and write it. If another application, file-sync tool, or backup tool is changing the Space, pause it and try opening the Space again.

An `.eidos` file must be a valid Eidos File. Renaming an ordinary SQLite database with an `.eidos` extension does not convert it.

## A file is busy or locked

Close other Eidos windows, SQLite tools, or preview apps that have the same `.eidos` file open, then try again. Do not let two applications write to the same file at once.

## Versions asks you to save changes first

Restore and Sync require a saved version of the current work:

1. Open **Versions** from the top-right corner.
2. Review the work under **Changes**.
3. Select **Save version**.
4. Try the original action again.

If you do not need the changes, you can discard them from **Changes**, but the discarded work cannot be recovered from the current working state.

## The Versions button is unavailable

Confirm that Eidos Lite can write to the Space folder, then reopen the Space. If it is still unavailable, check **Settings → Updates** and restart Eidos Lite.

## Sync says access is required

Sync is in a limited preview. Signing in does not automatically grant access. Open **Settings → Account & Services** to check the current account.

The local Space is unaffected and remains available offline.

## Sync cannot continue

Follow the main action shown in the Sync panel:

- **Review changes** — save a local version or resolve conflicts between Local and Hosted.
- **Manage storage** — clear cloud storage or change the plan.
- **Try again** — check the network connection and retry.
- **Sign in again** — the session expired and needs a new sign-in.

Do not delete the local Space to clear a Sync state. If there is a conflict and you are unsure what to keep, create recovery copies first.

## Publish is unavailable

Make sure that you are signed in and that Publish is available for the account. Eidos Lite currently publishes `.eidos`, `.md`, and `.markdown` files; folders and other formats do not offer Publish.

## A published attachment is missing

Make sure that the attachment still exists in the source file's folder or one of its subfolders. If it was moved or renamed, update its reference in the source and publish again.

## Find a deleted file

Ordinary files deleted from Eidos Lite move to the system Trash. Check the Trash first; if the file is not there, restore it from Version history or an independent backup.

## If the problem remains

Open **Settings → About**:

1. Select **Copy diagnostics**.
2. If needed, select **Show logs folder**.
3. Open a [GitHub issue](https://github.com/mayneyao/eidos/issues), describe the action and message you saw, and include the diagnostics.

Review logs before sharing them. Remove private file names, paths, or account details.
