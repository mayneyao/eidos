Your Space is a folder on your device. Keep its files and their referenced
attachments together when you move or back up your work.

## Follow the files

<FileMap />

An `.eidos` file stores tables, fields, records, formulas, and saved view
definitions. File fields store references: these can point to separate files
or contain supported inline data. Do not assume every attachment is inside
the database.

Images pasted into Markdown notes in Lite are saved in an `assets/`
folder beside the note. The note links to them with relative paths.

## Saving is one part of recovery

<DataChoices />

Versions and Sync serve different purposes from an independent backup.
Local history can be lost with its drive. Sync can carry unwanted changes
to another device.

## Make a backup you can restore

1. Finish editing and check that changes are saved.
2. Close the Space and stop other programs that write to its files.
3. Copy the whole Space to independent storage. Include hidden history files
   if you need to preserve local history.
4. Open a separate restored copy. Check important records, notes, and attachments.

If a live-backup tool copies open databases, use its documented consistent
snapshot method. Do not assume that copying an active SQLite database alone
captures all committed work.

File Metadata Management stores custom values in physical file attributes.
Check that your backup tool preserves those attributes.
Copying `files.eidos` alone does not back them up.
See [file metadata portability](/user-guide/file-metadata/).

## When a file is locked

Close the other editor that is writing to the file, then retry.
Do not remove lock or database sidecar files to force a file open.
See [troubleshooting](/user-guide/troubleshooting/).
