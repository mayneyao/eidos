Sync keeps a local copy of a Space on each device. Local files remain usable offline.

## Choose a sync method

| What you want to do                           | Recipe                                                       | Requirements                                                     |
| --------------------------------------------- | ------------------------------------------------------------ | ---------------------------------------------------------------- |
| Sync a phone and computer on the same network | [LAN sync](/recipes/sync-lan/)                               | Lite, a mobile app, and the same local network; no cloud account |
| Sync computers through the official service   | [Eidos Sync](/recipes/sync-eidos/)                           | An Eidos account with Sync access                                |
| Sync computers through your own server        | [Connect a self-hosted server](/recipes/sync-custom-server/) | Spark activated on each computer and a compatible Graft server   |

Need a server first? Follow [Deploy Graft on Cloudflare](/recipes/deploy-graft-cloudflare/) for one-click deployment and initial setup.

## After connecting

Open the Space's **Sync** panel and choose **Cloud sync** or **LAN sync**.
Under cloud sync, use **Server** to select Eidos Sync or a saved server.
Cloud sync supports macOS, Windows, and Linux. Each Space uses one cloud service
at a time; LAN sharing can remain enabled independently.

**Versions** manages local changes and version history. **Sync** manages connections,
transfers, and conflicts. After connecting, follow [Everyday cloud sync and recovery](/recipes/manage-cloud-sync/)
to send and receive versions, resolve conflicts, or recover access.

## Automatic Sync in Lite

In **Settings → Account & Services → Sync → Automatic Sync**, choose:

- **Every 10 minutes** (default): sync open, connected Spaces about every ten minutes.
- **After changes**: sync saved changes after a short delay, and still check for remote updates every ten minutes.
- **Off**: use the Sync panel to send and receive versions manually.

The default also applies to existing connections, including custom servers. It
does not connect local-only Spaces or sync folders whose windows are closed.
Lite waits for thirty seconds without interaction while it is in the foreground,
or a short pause after it moves into the background. Working in another app does
not prevent background Sync. Sleep and missed intervals do not create a backlog.

Automatic Sync creates a local checkpoint of saved changes using the same ignore
rules as manual checkpoints, then checks the remote and sends or receives
versions. Unsaved text drafts in any tab keep automatic Sync queued. Save them
before leaving the computer if you want those changes to sync.

Returning to Lite or using the keyboard or mouse cancels background scans and
transfers. A local fast-forward that has already begun replacing files must finish
validation and reopen the files safely before editing continues; this
local step cannot be interrupted. Manual Sync takes priority over automatic work.

Network and temporary server errors retry with increasing delays, up to fifteen
minutes between attempts, or longer if the server requests a cooldown. Password, account, quota, and history conflicts appear
in the existing Sync panel. Automatic Sync never resolves divergent history or
opens a recovery dialog. Use the panel to unlock, restore access, or review a
conflict, then sync manually to resume automatic work.

If a stalled transfer requires its background process to restart, session-only
unlock is lost. The Sync panel will ask for the password again unless the device
can restore a remembered password securely. Local files remain available.

## Keep a separate backup

Sync also transfers deletions to other devices. Keep an independent [backup](/user-guide/data-safety/).
Cloud sync's end-to-end encryption protects remote copies; it does not encrypt the local folder.
