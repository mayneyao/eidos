The canonical machine-readable contract is
[`extension-manifest.schema.json`](/schemas/extension-manifest.schema.json).

## Contract status

| Property         | Value                                           |
| ---------------- | ----------------------------------------------- |
| Manifest version | `1`                                             |
| Stability        | Frozen for foundation work; runtime unavailable |
| Unknown fields   | Rejected                                        |
| Identity         | Derived from `publisher.name`                   |
| Package root     | `.eidos/extensions/<publisher.name>/`           |
| Activation       | Derived from contributions                      |
| Permissions      | Declared maximum; grants are local              |

The schema is intentionally strict. A future additive capability that cannot be
represented safely will require a new manifest version rather than changing the
meaning of an existing field silently.

## Use in an editor

Add `$schema` to the root object:

```json
{
  "$schema": "https://docs.eidos.space/schemas/extension-manifest.schema.json",
  "manifestVersion": 1
}
```

## Validation order

1. Parse JSON and reject duplicate keys.
2. Validate against the manifest schema.
3. Derive the canonical package ID.
4. Require the directory name to match the canonical ID, then validate
   contribution IDs and entrypoint paths.
5. Check `engines.eidos` against the running host.
6. Reject unsupported imports and package-manager behavior.
7. Calculate the content digest and permission hash.
8. Validate any host-owned per-package `extension.lock.json` provenance.
9. Detect package identity conflicts in the Space.

Validation never executes package code or package-manager scripts.

## Dependency and provenance policy

Manifest version 1 accepts relative imports within the package and
`@eidos.space/extension-sdk` only. Bare third-party imports, Node.js or Electron
built-ins, non-literal dynamic imports, runtime CDN imports, and lifecycle
scripts are rejected. Eidos never runs `npm install` for an extension.

GitHub provenance is stored beside each installed package as the host-owned
`.eidos/extensions/<publisher.name>/extension.lock.json`; there is no
Space-wide extension lockfile. The version 1 content digest hashes the
normalized path and bytes of every package file except that lockfile. Trust is
keyed by canonical ID, content digest, and permission hash.

Package trees may contain regular files and directories only; symbolic links
and special files are rejected. Paths use UTF-8 NFC and `/`, are checked for
NFC and case-folding collisions, and are sorted by unsigned UTF-8 byte order.
SHA-256 receives one record per file:
`[u32be pathLength][pathBytes][u64be contentLength][contentBytes]`. Digests are
encoded as `sha256:<lowercase hex>`. Permission arrays are sorted and hashed
from RFC 8785 canonical JSON using the same encoding.
