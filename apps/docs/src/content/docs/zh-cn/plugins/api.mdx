在代码中使用 `import type` 从 `@eidos.space/plugin-sdk` 导入类型。Eidos 在调用 `mount` 或 `activate` 时提供上下文。

## 声明视图

`views` 中每个视图都需要 `id`、`title`、`entry` 和 `kind`。kind 为 `page` 或 `file`；access 为 `read` 或 `write`，默认 read。

文件视图在 capabilities 中声明需要的数据接口：`document` 用于文本编辑；`eidos/schema`、`eidos/table`、`eidos/config` 分别用于文件结构、当前表格和插件配置，可以组合声明。直接读取文件或播放媒体时，通过 fs 访问文件，capabilities 可以省略。文本和 Eidos 接口适用于不同文件格式，不能混合声明。

使用 placements 指定入口：navigation 与 plugin/settings 打开 page；file/open 根据扩展名打开 file；table/view 在表格内部打开声明了 eidos/table 能力的 file。

`requires.pluginApi` 声明插件要求的 API，本文示例使用 `"3.0.0"`。`apiVersion` 固定为 `1`，插件自己的 version 用于标识发布版本。

## 当前文件与页面

在使用 binding 前检查 kind。page 提供 route，file 提供 file 元数据，并可通过 location 描述表格位置。

```ts
if (ctx.binding.kind === "page") {
  root.textContent = ctx.binding.route
} else {
  root.textContent = ctx.binding.file.name ?? "File"
}
```

FileRef 的 path、name、size 等成员按运行环境提供。id 用于识别当前上下文中的文件；需要持久引用时，请使用你的业务数据中的稳定标识。

## 读取和编辑文本

声明 `capabilities: ["document"]` 后，通过 `ctx.capabilities.document` 使用以下方法。写入还需要 `access: "write"`。

| 方法                              | 用途                                       |
| --------------------------------- | ------------------------------------------ |
| `read()`                          | 获取包含 text、version、dirty 等信息的快照 |
| `observe(listener, onError?)`     | 获取初始快照并订阅后续变化                 |
| `edit({ text, expectedVersion })` | 修改未保存内容，返回 applied 或 stale      |
| `save()`                          | 保存到文件，返回 saved 或 conflict         |
| `undo()` / `redo()`               | 撤销或重做编辑并返回快照                   |

下面的函数体将当前文本转成大写并保存：

```ts
const document = ctx.capabilities.document
if (!document) throw new Error("Document capability required")
const current = await document.read()
const result = await document.edit({
  text: current.text.toUpperCase(),
  expectedVersion: current.version,
})
if (result.status === "stale") {
  await ctx.capabilities.ui.notify(
    "The text changed. Review it before editing again."
  )
  return
}
const saved = await document.save()
if (saved.status === "conflict") {
  await ctx.capabilities.ui.notify(
    "The file changed on disk. Your draft is still available."
  )
}
```

expectedVersion 使用读取时的版本。遇到 stale 时保留用户输入并让用户处理较新的内容；遇到 conflict 时保留草稿并提示磁盘变更。连续输入的编辑器应串行提交 edit，避免多个请求使用同一个旧版本。

## 读取文件和播放媒体

Lite 的 `ctx.capabilities.fs` 提供 readText/writeText、readBinary/writeBinary、list/stat、delete/rename、getUrl 和 watch。文本读取上限为 2 MiB，二进制 I/O 上限为 16 MiB；播放较大的媒体文件使用 getUrl 返回的流地址。

```ts
const fs = ctx.capabilities.fs
if (!fs) throw new Error("Filesystem access is required")
const video = document.createElement("video")
video.controls = true
video.src = await fs.getUrl()
root.append(video)
```

文件视图的文件访问受当前文件及其目录范围约束；访问整个 Space 需要 workspace.files。写入同时需要贡献项的 write 权限。已有工作副本的路径在直接写入、删除或重命名时会返回 BUSY；编辑文本时使用 document 接口处理保存和冲突。

## 使用 Eidos 文件

`ctx.capabilities.eidos` 包含按需声明的 `schema`、`table` 和 `config`。例如，一个需要读取结构和保存本插件配置的表格视图可以声明：

```json
{
  "id": "board",
  "title": "Board",
  "kind": "file",
  "entry": "./src/board.ts",
  "capabilities": ["eidos/schema", "eidos/table", "eidos/config"],
  "access": "write"
}
```

为此视图添加 `table/view` 入口。每项声明只提供对应接口；声明顺序不影响行为。

### 浏览文件结构

声明 `eidos/schema`，使用 `ctx.capabilities.eidos.schema.listTables()` 获取文件内的表格列表，再用 `readTable(tableId)` 读取字段。文件浏览器通过匹配 `.eidos` 的 `file/open` 入口打开；表格视图也可以读取所在文件的结构。

### 查询当前表格

声明 `eidos/table` 并从 `table/view` 打开后，使用 `ctx.capabilities.eidos.table`：readContext 读取当前表格结构和视图信息，readRows 分页读取记录，aggregate 聚合数据，setViewConfig 完整替换当前视图的插件配置，openRecord 打开记录，watch 订阅失效通知。先读取结构，再用字段 ID 查询；这些方法始终作用于当前绑定表格。

### 保存插件配置

声明 `eidos/config`，通过 `ctx.capabilities.eidos.config` 的 read、write、watch 使用保存在文件中的本插件配置。文件浏览器可指定文件内的表格 ID；表格视图使用当前绑定的表格 ID。

```ts
const { table, config } = ctx.capabilities.eidos ?? {}
if (!table || !config) throw new Error("Table and config capabilities required")
const current = await config.read(table.tableId)
await config.write(table.tableId, {
  value: { ...current.value, compact: true },
  expectedVersion: current.version,
})
```

写入需要 `access: "write"` 和读取时的版本。版本过期时重新读取并处理冲突，避免覆盖他人的修改。`config.watch(tableId, listener)` 返回订阅，不发送初始值；先读取配置，收到通知后再次读取。通知可能包含其他数据变化，释放订阅后停止接收。

Lite 支持以上三个接口。CLI Serve 提供 `eidos/table`；需要同时支持 Serve 时，只声明该宿主提供的能力，并通过 `check --target cli` 验证。

## 设置、存储和通知

Lite 视图通过 capabilities.settings.get(key) 读取插件设置；普通动作还可调用 set/reset。capabilities.storage 提供按 key 存取私有二进制数据的 list/read/write/delete，配额通过 manifest.storage.maxBytes 声明。这些私有数据保存在设备本地。

capabilities.ui.notify(message) 显示通知。在支持导航的环境中，ui.openFile(relativePath) 打开文件，ui.navigate(viewId, route?) 打开页面。可选方法在调用前检查其是否存在。

capabilities.network.read({ url }) 向 browser.networkOrigins 声明的 HTTPS 来源发起有界请求。需要凭据的请求通过 `ctx.capabilities.connections` 的 `isConfigured(connectionId)` 和 `request({ connection, body })` 调用已声明连接。连接可用于页面、文件视图和普通动作，由用户在 Eidos 中配置连接信息和密钥；动作结束时请求会被取消。

## 注册命令与格式化器

在扩展的 activate 中使用 capabilities.actions.register(id, handler) 注册声明过的动作。handler 接收自己的上下文，通过 capabilities 执行操作。

格式化器通过 capabilities.formatters.register(id, provider) 注册。provider.format 接收 `{ text, path, signal }` 并返回 `{ text }`，由 Eidos 应用可撤销的文本编辑。

## 批量处理表格记录

使用 capabilities.actions.registerTableProvider(id, provider) 注册表格动作。getItems 接收 capabilities.eidos.table、只读的 capabilities.eidos.config 和 signal，返回供用户选择的菜单项；run 还可使用 capabilities.target、task 和 connections。

target.count 表示本次目标总数，target.readRows 分页读取记录。使用返回的 readToken 调用 target.update。开始写入前，调用 task.declareOutputs 提交真实输出样本并等待校验完成，它用于确定允许写入的字段。调用 task.report 报告进度，在每批操作之间检查 signal。取消会保留已经完成的记录修改。

## 释放资源与处理错误

把订阅加入 ctx.subscriptions，使用 ctx.signal 中止异步操作，并在 mount 返回的 dispose 中释放界面资源。

常见错误包括 PERMISSION_DENIED（访问范围不足）、INSTANCE_CLOSED（上下文已关闭）、STALE_REVISION（数据已变化）、BUSY（资源正在被管理）、TOO_LARGE（超过限制）和 TIMEOUT（请求超时）。向用户说明失败原因，保留尚未保存的输入。

完整签名见 [SDK 类型定义](https://github.com/mayneyao/eidos/blob/dev/packages/plugin-sdk/src/index.ts)，行为约定见[插件规范](https://github.com/mayneyao/eidos/blob/dev/docs/specs/eidos-lite-plugins-1.0.md)。
