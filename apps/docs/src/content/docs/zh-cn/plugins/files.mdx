## 读取和编辑文本

声明 `capabilities: ["document"]` 后，通过 `ctx.capabilities.document` 使用以下方法。写入还需要 `access: "write"`。

| 方法                              | 用途                                       |
| --------------------------------- | ------------------------------------------ |
| `read()`                          | 获取包含 text、version、dirty 等信息的快照 |
| `observe(listener, onError?)`     | 获取初始快照并订阅后续变化                 |
| `edit({ text, expectedVersion })` | 修改未保存内容。返回 applied 或 stale      |
| `save()`                          | 保存到文件。返回 saved 或 conflict         |
| `undo()` / `redo()`               | 撤销或重做编辑并返回快照                   |

下面的函数体将当前文本转成大写并保存：

```ts
const document = ctx.capabilities.document
if (!document) throw new Error("Document capability required")
const current = await document.read()
const result = await document.edit({
  text: current.text.toUpperCase(),
  expectedVersion: current.version,
})
if (result.status === "stale") {
  await ctx.capabilities.ui.notify(
    "The text changed. Review it before editing again."
  )
  return
}
const saved = await document.save()
if (saved.status === "conflict") {
  await ctx.capabilities.ui.notify(
    "The file changed on disk. Your draft is still available."
  )
}
```

expectedVersion 使用读取时的版本。遇到 stale 时保留用户输入并让用户处理较新的内容。遇到 conflict 时保留草稿并提示磁盘变更。连续输入的编辑器应串行提交 edit，避免多个请求使用同一个旧版本。

## 读取文件和播放媒体

Lite 的 `ctx.capabilities.fs` 提供 readText、writeText、readBinary、writeBinary、list、stat、delete、rename、getUrl 和 watch。
文本读取上限为 2 MiB，二进制 I/O 上限为 16 MiB。
播放较大的媒体文件使用 getUrl 返回的流地址。

```ts
const fs = ctx.capabilities.fs
if (!fs) throw new Error("Filesystem access is required")
const video = document.createElement("video")
video.controls = true
video.src = await fs.getUrl()
root.append(video)
```

文件视图的文件访问受当前文件及其目录范围约束。访问整个 Space 需要 `workspace.files`。写入同时需要贡献项的 write 权限。已有工作副本的路径在直接写入、删除或重命名时会返回 BUSY。编辑文本时使用 document 接口处理保存和冲突。

## Lite 文件属性

Lite API 3.1 通过 `ctx.capabilities.filemeta` 读取和修改原生 namespace 属性，底层由 sqlite-fs-meta 实现。
声明需要访问的 namespace。写入同时要求 View 或 Action 的 `access: "write"`。Page 浏览 Space 文件还需要 workspace 文件读权限。

```json
{
  "workspace": {
    "files": { "read": true },
    "filemeta": { "namespaces": ["space.eidos.meta"], "write": true }
  }
}
```

```ts
const filemeta = ctx.capabilities.filemeta!
const metadata = await filemeta.read("notes/example.md", "space.eidos.meta")
await filemeta.patch("notes/example.md", "space.eidos.meta", {
  set: { rating: 4, tags: ["review"], custom: { checked: true } },
  remove: ["obsolete"],
})
```

读取返回完整 JSON 对象，包括 `files.eidos` 未定义的键。namespace 不存在时返回 `{}`。patch 保留其他键，null 是值，remove 数组删除键。路径相对 Space。未声明 workspace 文件读权限时，只能访问绑定文件。属性写权限不授予文件内容写权限。损坏的 JSON、符号链接、非普通文件会报错。属性最多 1 MiB，文件系统可能有更小限制。操作立即作用于文件系统。多个进程修改同一 namespace 时应串行协调写入。Linux 不需要安装 `attr` 命令行软件包。

## 释放资源与处理错误

把订阅加入 `ctx.subscriptions`，使用 `ctx.signal` 中止异步操作，并在 `mount` 返回的 `dispose` 中释放界面资源。

常见错误包括 PERMISSION_DENIED（访问范围不足）、INSTANCE_CLOSED（上下文已关闭）、STALE_REVISION（数据已变化）、BUSY（资源正在被管理）、TOO_LARGE（超过限制）和 TIMEOUT（请求超时）。向用户说明失败原因，保留尚未保存的输入。

完整签名见 [SDK 类型定义](https://github.com/mayneyao/eidos/blob/dev/packages/plugin-sdk/src/index.ts)，行为约定见[插件规范](https://github.com/mayneyao/eidos/blob/dev/docs/specs/eidos-lite-plugins-1.0.md)。
