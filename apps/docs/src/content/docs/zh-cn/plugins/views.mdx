## 声明视图

### 文件模板与 Dashboard

Lite 插件 API 3.2 的 `fileTemplates` 可向“新建文件”添加格式选项。每项声明
`id`、`title`、`extension`、`view` 和 `content`，content 为最多 256 KiB 的静态 UTF-8 文本。
view 必须具有 document 能力及匹配扩展名的 file/open 放置。宿主以不覆盖方式创建文件，并打开对应 View。

具有 `workspace.files.read` 权限的 file View 可以检测可选的
`ctx.capabilities.ui.resources`。`listViews(relativePath)` 列出另一份 `.eidos`
文件的表和已保存视图。`mount(element, { kind: "eidos-view", path, tableId, viewId })`
将其挂载到矩形容器。普通文本、Markdown、图片使用 `{ kind: "file", path }`。
GPX 等普通文件的 listViews 返回已启用且匹配的插件 View 与内置预览，结构为
`{ kind: "file", editor, name, type }`。将选中的 editor 加入 file source 即可保存展示方式。
返回句柄应加入 subscriptions，支持 `refresh()` 和 `dispose()`。

路径相对于当前配置文件解析，必须位于同一 Space。最多 12 个只读资源，
不支持嵌套 dashboard、变换或重叠交互控件。宿主管理渲染和独立授权，
子插件通过 `ctx.presentation?.mode === "embedded"` 精简界面。
该能力目前由 Lite 提供。

`views` 中每个视图都需要 `id`、`title`、`entry` 和 `kind`。kind 为 `page` 或 `file`。access 选项为 `read` 或 `write`，默认设置是 `read`。

文件视图在 capabilities 中声明需要的数据接口：`document` 用于文本编辑。`eidos/schema`、`eidos/table`、`eidos/config` 分别用于文件结构、当前表格和插件配置，可以组合声明。直接读取文件或播放媒体时，通过 fs 访问文件，capabilities 可以省略。文本和 Eidos 接口适用于不同文件格式，不能混合声明。

使用 placements 指定入口。navigation 与 plugin/settings 打开 page。file/open 根据扩展名打开 file。table/view 在表格内部打开声明了 eidos/table 能力的 file。

在 Lite 中，侧栏底部依次显示设置、插件和最多三个已启用插件的独立页面。页面默认按原有顺序排列。超过三个页面时，「…」菜单列出全部页面，支持固定和拖拽排序。拖拽手柄也支持键盘操作。最多固定三个页面，保证它们占据可见位置，其余位置按保存的顺序补齐。固定状态和顺序按 Space 保存在本机。窄侧栏下显示图标，悬停可查看名称。专用于 `plugin/settings` 或 `sidebar/explorer` 的页面不会出现在此处，除非同时声明了 `navigation` 挂载点。显示入口不会加载页面内容。

`requires.pluginApi` 声明插件要求的 API，本文示例使用 `"3.0.0"`。`apiVersion` 固定为 `1`，插件自己的 version 用于标识发布版本。

可以在清单中添加 `description`，说明插件的具体用途。使用非空的单行纯文本，
最多 1024 个 UTF-16 码元。Lite 在插件列表和详情中显示该摘要，本地安装的插件
也适用。缺失时，如果插件市场有对应描述，则使用市场描述。

```json
"description": "Keep Markdown filenames and existing leading H1 headings in sync."
```

## 当前文件与页面

在使用 binding 前检查 kind。page 提供 route，file 提供 file 元数据，并可通过 location 描述表格位置。

```ts
if (ctx.binding.kind === "page") {
  root.textContent = ctx.binding.route
} else {
  root.textContent = ctx.binding.file.name ?? "File"
}
```

FileRef 的 path、name、size 等成员按运行环境提供。id 用于识别当前上下文中的文件。需要持久引用时，请使用你的业务数据中的稳定标识。
