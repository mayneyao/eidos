每次提交新插件或更新前，用这份清单检查**准备上架的 `.eidos-plugin` 安装包**。开发者和 Agent 可以在同一份提交说明里记录支持范围、复现步骤和已知限制。

插件可以只支持 Eidos Lite。只对已验证的宿主、设备和工作流声明支持。

## 上架前检查

### 发布包与核心流程

- [ ] 运行目标宿主的检查和项目测试，再打包。用将要发布的归档在目标宿主中安装，检查请求的权限，从用户会使用的入口跑通核心流程。主题包在 Lite 中启用，分别检查亮色和暗色外观。
- [ ] 测试与插件相关的失败场景，例如空文件、无记录、权限被拒、断网或服务超时。用户能理解发生了什么，并能返回或重试。
- [ ] 更新时保留插件 ID、视图 ID 和设置键，增加版本号。用已有数据的副本验证升级，检查已保存的视图、设置和文件。

### 宿主与移动端

使用 `eidos-plugin check . --target lite` 检查 Lite 的能力声明，使用 `--target cli` 检查 CLI Serve。iOS 和 Android 分别在各自的应用内验收。

- [ ] 分别记录 **Eidos Lite、iOS、Android、CLI Serve** 的状态。使用「支持」「有限支持」「未验证」或「不支持」。按宿主填写测过的应用版本、系统或设备，以及实际入口。只在证据充分时声明最低支持版本。
- [ ] 若声明移动端支持，在 **Eidos iOS 或 Android 应用**中验证相应平台。打开一个视图之后继续完成核心操作，例如用示例文件编辑、保存并重新打开。包检查、桌面窗口缩放和浏览器预览可补充说明测试范围。
- [ ] 按已声明的设备类型检查手机窄屏、软键盘、触摸和滚动。支持平板时，检查宽屏、横竖屏以及布局或导航是否仍可用。依赖 WebGL、系统文件选择器等平台行为时，优先补充真机验收。
- [ ] 运行时检查可选 API。缺少桌面能力时，隐藏不可用的控件或提供可用的替代路径，并在市场说明和 README 中解释差异。例如移动端可以查看图表，而 PNG 导出只在已验证的宿主提供。核心流程缺少必需能力的宿主应标为不支持。

### 多语言与市场资料

- [ ] 默认语言的市场名称、简介、界面和使用说明完整。确认标签、错误、空状态和无障碍名称都能理解。
- [ ] 列出实际提供的语言。如果声明多语言，验证市场名称与说明、界面和 README 的语言与回退。用较长的译文检查手机布局。翻译配置见[插件多语言](/zh-cn/plugins/i18n/)。
- [ ] 市场简介描述用户能做什么，兼容性说明写清限制和外部依赖。README 提供可复现的上手步骤和反馈入口。提交截图时使用对应版本的实际界面，并用示例数据。

### 权限与数据

- [ ] 声明核心流程所需的最小权限。README 写清插件会读写哪些数据、何时自动执行，以及哪些内容会发送到外部服务。
- [ ] 对写入、批量操作或外部连接，验证适用的确认、取消与错误处理。验收材料可以提供示例文件或演示模式，请去除访问令牌、密钥和用户数据。

## 提交市场目录

1. 按[开发与分发](/zh-cn/plugins/workflow/)检查和打包，在公开 GitHub Release 上传验收用的 `<id>-<version>.eidos-plugin`。
2. 用 `eidos-plugin registry --help` 查看参数，从同一归档生成市场条目草稿。核对版本、实际 tag、文件名、SHA-256、分类和兼容性。主题包按目录的主题说明提交。
3. 按[市场仓库的贡献说明](https://github.com/eidos-space/registry/blob/main/CONTRIBUTING.md)更新 `plugins.registry.json`，在 PR 中附上验收结果。
