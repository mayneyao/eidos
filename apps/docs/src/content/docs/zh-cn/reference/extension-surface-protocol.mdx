`@eidos.space/extension-surface-protocol` 是 custom extension UI 的 transport 与 document-state
contract。它不包含 React、Electron、iframe、filesystem 或 editor 实现。File-based extension RFC
的 P3a 已在这个 package 中实现；Desktop 激活第三方 UI entrypoint 仍属于 preview work。

## Version 1 固定不变量

| 不变量            | Version 1 规则                                                     |
| ----------------- | ------------------------------------------------------------------ |
| Offset unit       | JavaScript UTF-16 code unit，不是 Unicode code point 或 UTF-8 byte |
| Revision          | 由宿主拥有的正数、单调递增整数                                     |
| Edit base         | 同一 batch 的所有 edit 都针对完全相同的 `baseRevision`             |
| Document owner    | 宿主拥有 text、dirty、undo/redo、save 与 conflict state            |
| Surface authority | Surface 只能请求有界 edit，不能直接写文件                          |
| Save              | Host-internal、single-use compare-and-swap token                   |
| Multiple views    | 一个 document model 向所有 attached view 广播 accepted edit        |
| Conflict choice   | Reload 或 overwrite 由 host UI 决定，extension code 不能静默选择   |

首个 editable surface 的 protocol limit 有意保持较小：

- 一个 batch 最多 128 条 edit；
- 最多插入 256 Ki UTF-16 code unit；
- inserted 与 removed text 合计最多变更 256 Ki UTF-16 code unit；
- 一个 text document 最多 512 Ki UTF-16 code unit。

调用方可以降低限制，不能提高 version 1 固定上限。更大的文档继续回退到 native text preview，直到
streaming contract 可用。

## Connection 与 capability negotiation

宿主向一个 sandboxed surface 转移专用 `MessagePort`。Surface 发送 `ready` 后，宿主发送一次
`initialize`，其中包含：

- `protocolVersion`；
- immutable package `generation`；
- `editorId` 与唯一 `viewId`；
- 完整 initial document snapshot；
- `editable`、`save`、`undoRedo` 与 `savePolicy` 等 capability；
- `appearance`，包含 locale、明暗配色和一组固定的已解析主题值。

Surface 不能根据自己的 Manifest 猜测 capability。例如，即使 package 请求了 write access，只要
`editable` 为 false 就必须展示 read-only UI。不支持的 protocol version 会关闭 port，Eidos 回退到其他
compatible editor 或 native editor。

只有 bootstrap 使用 `window.postMessage` 转移 port，document traffic 全部留在该 port。Surface 不会获得
Electron bridge、host DOM、raw filesystem handle、SQLite connection 或 unrestricted network client。

Runtime 会把外观值映射为稳定的 CSS 自定义属性，例如
`--eidos-color-background`、`--eidos-color-foreground`、
`--eidos-color-border`、`--eidos-color-accent`、
`--eidos-color-focus-ring`、`--eidos-font-family` 和
`--eidos-font-family-mono`。后续 `appearance-changed` 消息会在不重新激活
扩展的情况下更新这些值。扩展 UI 不应依赖 Eidos class，也不能检查宿主 DOM。

## 应用一条 edit

假设 revision 7 包含：

```md
- [ ] Ship surface protocol
```

勾选任务只变更一个 UTF-16 code unit。Surface 发送：

```ts
port.postMessage({
  type: "apply-edits",
  requestId: "edit-42",
  documentId: snapshot.documentId,
  baseRevision: 7,
  edits: [{ start: 3, end: 4, text: "x" }],
})
```

宿主 parse unknown message、验证全部边界，只在 revision 7 仍是 current 时应用；随后记录用于 undo 的
inverse edit、前进到 revision 8，并向所有 view 广播 `document-changed`。仍针对 revision 7 提交的另一个
view 会收到 `STALE_REVISION` 并请求完整 `resync`；宿主不会猜测如何 merge stale offset。

## Undo、redo 与多个 view

Undo/redo 是 document operation，不是 iframe-local history。任意 view 发出的请求都会推进 shared
revision，并生成所有 view 都要应用的 minimal edit。Surface 可以保留 selection、filter 等 transient UI
state，但不能自行宣称 document 已 dirty 或 saved。

Broadcast 包含 `originViewId`，它只用于 attribution，不表示 origin view 可以忽略 update；origin view 也必须
前进到 broadcast revision。

## Save 与 external change

`request-save` 请求宿主保存 current revision。在宿主内部，document model 签发有界、single-use token，
包含 exact text 和它所基于的 persisted content digest。Filesystem writer 替换文件前仍必须观察到同一个
digest。

较早的 save 可能在较新的 edit 后完成。这时它只更新 saved baseline，较新的内存 text 仍保持 dirty；旧
save 永远不会覆盖较新输入。Replay、alter、cancel 或超过 in-flight 上限的 token 都会被拒绝。

File watcher 观察到新 digest 时：

1. Clean document 直接 reload external snapshot、清空 history，并广播 `document-replaced`。
2. Dirty document 进入 `externalConflict`，save 被阻止。
3. Host UI 让用户选择 **Reload** 或 **Overwrite**。
4. Reload 接受 external text；Overwrite 保留 local text，但把 compare-and-swap baseline 更新为刚观察到的
   external digest。

Extension 不能自行隐藏或解决该 conflict。

## Surface-to-host request

| Message                         | 用途                                            |
| ------------------------------- | ----------------------------------------------- |
| `ready`                         | 完成 protocol handshake                         |
| `activated`                     | 确认 UI 已成功激活                              |
| `activation-error`              | 报告有长度限制的激活错误                        |
| `apply-edits`                   | 针对 exact revision 提交一个 bounded batch      |
| `request-save`                  | 请求宿主 persist current revision               |
| `request-undo` / `request-redo` | 操作 shared document history                    |
| `request-resync`                | 使用完整 host snapshot 替换 surface local state |
| `closed`                        | 告诉宿主 surface 已自行 dispose                 |

每个 request 都会收到 `request-result`。稳定 failure code 包括 `INVALID_EDIT`、`STALE_REVISION`、
`READ_ONLY`、`CONFLICT`、`RUNTIME_STALE` 与 `NOT_AVAILABLE`。Protocol error 是 data；malformed surface
message 不能让 host process crash。

## 开发检查清单

- Parse initial snapshot，但不重写它。
- 使用 JavaScript string 的 UTF-16 offset。
- 针对 last accepted revision 提交 minimal edit。
- 应用每一条 host broadcast，包括 attribution 指向当前 view 的 broadcast。
- 收到 `STALE_REVISION` 后请求 resync。
- Save、undo 与 dirty UI 只来源于 host state。
- 缺少 capability 时禁用功能，不能用 direct file access 补洞。
- Surface 关闭时 dispose listener 与 port。

第一个 proof surface 会是 editable Markdown Task Board。它通过本协议切换 checkbox marker，同时保留 Eidos
正常的 file save、undo、external-change 和 Graft 行为。
