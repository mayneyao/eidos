`@eidos.space/base-ui` 的目标是成为开放 `.base` 格式的可复用 React 编辑器。当你的应用需要
兼容 Eidos 的多维表格和视图，但不想嵌入整个 Eidos Desktop 时，可以使用这个 package。

:::caution[本页定义的是目标公开 API]
Package 已经提供共享 Grid、Gallery、Kanban、data source 和 renderer 实现，但下文按需加载的
plugin factory 尚未实现。这些示例描述的是正式发布受支持版本前，希望稳定下来的 package 边界。
目前可用的能力请查看[当前 API 与迁移](#当前-api-与迁移)。
:::

## 选择编辑器需要支持的视图

默认 package 应提供完整的 Grid 编辑器，其他视图由应用显式添加：

| 你要构建的产品           | 需要增加的 import                                 |
| ------------------------ | ------------------------------------------------- |
| 只有 Grid 的 Base 编辑器 | `@eidos.space/base-ui`                            |
| Grid 与 Gallery          | `@eidos.space/base-ui/gallery`                    |
| Grid 与 Kanban           | `@eidos.space/base-ui/kanban`                     |
| Grid、Gallery 与 Kanban  | 同时引入两个可选视图模块                          |
| Grid 与自己的视图        | `@eidos.space/base-ui/view-api` 和自己的 renderer |

引入根 package 不应在全局注册可选视图。引入 Gallery 不应把 Kanban 打进应用 bundle，引入
Kanban 也不应要求同时注册 Gallery。内部可以复用并去重 record card 等基础组件，但不能改变这条
面向消费者的契约。

## 从 Grid 开始

安装 runtime contract 与 UI package。React、React DOM 和 Glide Data Grid 继续作为 peer
dependency，由应用决定版本。

```sh
pnpm add @eidos.space/base @eidos.space/base-ui \
  @glideapps/glide-data-grid react react-dom
```

在应用入口全局引入一次公共样式：

```ts
import "@eidos.space/base-ui/styles.css"
```

然后提供基于 worker 的 `BaseEditorDataSource` 并渲染编辑器。Grid 无需额外 view plugin：

```tsx
import {
  BaseEditor,
  BaseUIProvider,
  type BaseEditorDataSource,
} from "@eidos.space/base-ui"

export function TasksBase({ source }: { source: BaseEditorDataSource }) {
  return (
    <BaseUIProvider
      themeName="light"
      locale="zh-CN"
      resolveAssetUrl={(path) => `/files/${encodeURIComponent(path)}`}
    >
      <BaseEditor
        source={source}
        tableId="tasks"
        onError={(error) => console.error(error)}
      />
    </BaseUIProvider>
  )
}
```

没有传入 `viewId` 时，`BaseEditor` 应打开该 table 的第一个已保存视图。如果当前宿主不支持
这个 view type，应显示 unsupported-view 状态并允许用户选择其他视图，不能静默把已保存视图
改成 Grid。

`locale` 是目标 provider option。Package 应默认支持英文与简体中文；宿主也可以在不 fork
renderer 的情况下提供更多 message catalog。

## 添加 Gallery

在应用边界添加 Gallery。已保存的 view 仍然来自 `.base` 文件；plugin 只为
`type="gallery"` 提供 React 实现。

```tsx
import { BaseEditor } from "@eidos.space/base-ui"
import { galleryView } from "@eidos.space/base-ui/gallery"
import "@eidos.space/base-ui/gallery/styles.css"

const viewPlugins = [galleryView()]

export function TasksBase({ source }) {
  return (
    <BaseEditor source={source} tableId="tasks" viewPlugins={viewPlugins} />
  )
}
```

`galleryView()` 应从 view metadata 读取 card size、cover、visible field 等保存设置。打开记录、
解析 asset、上报错误等应用级行为属于 `BaseEditor` 或 `BaseUIProvider`，不应写入 `.base` 文件。

如果文件包含 Gallery view，但宿主没有引入 `galleryView`，宿主应明确说明 Gallery 当前不可用。
数据与 view metadata 必须保持不变。

## 添加 Kanban

Kanban 使用相同模式：

```tsx
import { BaseEditor } from "@eidos.space/base-ui"
import { kanbanView } from "@eidos.space/base-ui/kanban"
import "@eidos.space/base-ui/kanban/styles.css"

const viewPlugins = [kanbanView()]

export function TasksBase({ source }) {
  return (
    <BaseEditor source={source} tableId="tasks" viewPlugins={viewPlugins} />
  )
}
```

Kanban 除分页记录外，还需要 runtime group count。只注册 plugin 还不够，host adapter 也必须提供
该 capability。缺失时，编辑器应报告具体能力缺失，不能拉取整张表后在 React 主线程分组。

如果同时支持两个可选视图，传入两个 plugin：

```ts
import { galleryView } from "@eidos.space/base-ui/gallery"
import { kanbanView } from "@eidos.space/base-ui/kanban"

const viewPlugins = [galleryView(), kanbanView()]
```

Plugin 顺序不能改变已保存视图的行为。同一 type 注册两次时，应在开发环境立即报错，不能静默
选择其中一个。

## 提供数据，但不让 UI 耦合 SQLite

所有视图都通过 `BaseEditorDataSource` 读写。浏览器、Electron 应用或原生 wrapper 负责 worker
与文件生命周期；Base UI 只负责 React 行为。

```ts
const source: BaseEditorDataSource = {
  getSnapshot: () => worker.call({ type: "snapshot" }),
  getPage: (tableId, offset, limit, query, totalHint, cursor, projection) =>
    worker.call({
      type: "page",
      tableId,
      offset,
      limit,
      query,
      totalHint,
      cursor,
      projection,
    }),
  getRow: (tableId, rowId) => worker.call({ type: "row", tableId, rowId }),
  getGroupCounts: (tableId, columnName, query) =>
    worker.call({ type: "group-counts", tableId, columnName, query }),
  insertRow: (tableId, row) =>
    worker.call({ type: "insert-row", tableId, row }),
  updateRow: (tableId, rowId, changes) =>
    worker.call({ type: "update-row", tableId, rowId, changes }),
}
```

Adapter 必须调用 `@eidos.space/base` 完成校验、查询、分组、migration 和 mutation。UI plugin
不能自行把 filter 编译成 SQL，也不能直接写 SQLite 文件。

### Capability matrix

| 视图    | 必需的 data-source capability                                |
| ------- | ------------------------------------------------------------ |
| Grid    | Snapshot、分页记录、记录更新；按启用功能提供 field/view 写入 |
| Gallery | Grid 记录访问、cursor paging、projection、完整记录 inspector |
| Kanban  | Gallery 记录访问、group count、按组分页、插入记录            |

编辑器应在挂载 renderer 前确认支持情况。只读 source 可以挂载 plugin，但必须禁用 mutation action；
缺少必需读取能力时则不能挂载。

## 发布自己的视图 plugin

自定义 view plugin 将持久化的 `view.type` 连接到 React renderer，不会创建第二套 schema 或 query
语言。

目标 helper 是 `defineBaseView`：

```tsx
import { defineBaseView } from "@eidos.space/base-ui/view-api"

interface TimelineProperties {
  startField: string
  endField?: string
  zoom?: "day" | "week" | "month"
}

export const timelineView = defineBaseView<TimelineProperties>({
  type: "acme.timeline",
  displayName: "Timeline",
  requiredCapabilities: ["page", "updateRow"],
  parseProperties(value) {
    if (
      !value ||
      typeof value !== "object" ||
      typeof (value as Record<string, unknown>).startField !== "string"
    ) {
      throw new Error("Timeline 需要开始时间字段")
    }
    return value as TimelineProperties
  },
  Renderer: TimelineRenderer,
  PropertyEditor: TimelinePropertyEditor,
})
```

注册方式与内置可选视图相同：

```tsx
<BaseEditor source={source} tableId="tasks" viewPlugins={[timelineView]} />
```

一个公开 plugin 应负责：

- 稳定且最好带命名空间的 view `type`；
- properties 解析，以及用户可理解的无效配置状态；
- renderer，以及需要时的 property editor；
- 声明它需要的 data-source capability；
- 自己的样式与本地化消息；
- paging、mutation failure、read-only、keyboard access 和未知 property 保留测试。

它不应负责 migration、SQL 生成、file handle、save state、conflict resolution 或 Base metadata
table。这些仍属于 runtime 与 host。

## 宿主仍然负责什么

Base UI 是编辑器 surface，不是文件管理器。嵌入它的应用继续负责：

- 打开 `.base` 文件并创建 runtime worker；
- dirty、saving、saved、error 与 conflict 状态；
- recovery、Save As、外部修改检测与写回；
- 当前 theme 与 locale；
- asset URL、file preview 与 record navigation；
- permission prompt 与 read-only policy。

通过这条边界，浏览器编辑器、Desktop 应用和第三方产品可以共享同一套视图实现，而不必共享
文件访问代码。

## 稳定发布前的 package 保证

可发布 package 应满足以下条件：

1. 根 export 只包含 editor shell、公共 contract 与默认 Grid。
2. Gallery 和 Kanban 使用稳定 subpath export，可从 JavaScript 与 CSS bundle 中完全移除。
3. 公开模块不能 import `apps/web-app` 或 `apps/desktop`。
4. Renderer 只接收 runtime 规范化后的 row 和 query，不能拥有 Base SQL 语义。
5. 未知 view type 与 properties 必须无损 round-trip。
6. Plugin 注册只属于当前 editor instance；import module 不产生全局副作用。
7. 缺少 plugin 或 capability 时提供可操作提示，不能静默 fallback。
8. 公共 type、style、peer dependency 与浏览器要求遵循 semantic versioning。

## 当前 API 与迁移

目前 `0.1` package 已暴露 Eidos Desktop 与 Base Web 共用的低层能力：

```tsx
import {
  BaseEditorView,
  BaseUIProvider,
  type BaseViewRendererRegistry,
} from "@eidos.space/base-ui"
```

`BaseEditorView` 接收已经选中的 table、view、data source 和 renderer registry。Gallery 和
Kanban 也有公开 component subpath。这足以供可信应用集成，但当前根 view router 仍静态 import
所有内置 renderer，因此还没有实现本文描述的按需 bundle 边界。

拟议迁移会保留低层 renderer contract，并新增：

| 拟议 API                  | 用途                                 |
| ------------------------- | ------------------------------------ |
| `BaseEditor`              | 默认带 Grid 的高层 table/view editor |
| `galleryView()`           | 按需启用 Gallery                     |
| `kanbanView()`            | 按需启用 Kanban                      |
| `defineBaseView()`        | 定义带类型的第三方 plugin            |
| `viewPlugins`             | editor instance 内注册               |
| Capability declaration    | host adapter 不完整时提前失败        |
| 每种视图独立 style export | Grid-only 应用不加载可选 CSS         |

`.base` metadata 与当前低层 renderer 示例请继续阅读
[Base 格式与自定义视图](/zh-cn/reference/base-custom-views/)。

## 可信 plugin 与沙箱 extension

View plugin 会在嵌入应用中直接运行 React。只能安装可信代码，并像审查其他应用依赖一样审查它。

这套 API 与沙箱 Eidos Extension SDK 相互独立。未来 extension contribution 可以复用相同数据与
view 概念，但必须经过隔离的 capability bridge，不能直接获得 `BaseEditorDataSource` 或宿主 React
访问权。
