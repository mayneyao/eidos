## 命令模型

帮助信息使用 command-first 语法：

```bash
eidos inspect tracker.eidos
eidos context tracker.eidos Tasks --fields Title,Status --limit 50
eidos validate tracker.eidos --level full
```

为兼容旧工作流，也接受 `eidos tracker.eidos inspect` 这样的 file-first 写法。新脚本建议使用
command-first，与 `eidos --help` 保持一致。

命令默认输出便于阅读的键值区块和表格。Agent 与脚本应显式传入全局 `--json` 参数：

```bash
eidos --json context tracker.eidos Tasks --fields Title,Status --limit 50
```

JSON 模式下，成功命令向 stdout 写一个 JSON document；失败命令向 stderr 写一个 JSON
error document，并返回非零 exit status。JSON schema 是稳定的自动化合同；人类可读输出可能
继续为可读性优化。

## 支持边界

CLI 负责 Eidos File 的创建、检查、查询、修改、校验与服务。Publish 同时接受带本地附件的
Eidos File 和 Markdown 文档。除此以外，CLI 不管理普通文档、Eidos Lite Space 生命周期、
应用 RPC、本地版本历史或同步。普通文件使用普通文件工具，历史使用 Graft-aware 工作流。

Raw SQLite write 不是受支持的自动化接口。
