## 基础使用

新的工作流建议使用命令优先的写法：

```bash
eidos inspect tracker.eidos
eidos context tracker.eidos Tasks --fields Title,Status --limit 50
eidos validate tracker.eidos --level full
```

命令默认输出便于阅读的结果。脚本或智能体需要稳定的结构化结果时，添加 `--json`：

```bash
eidos --json context tracker.eidos Tasks --fields Title,Status --limit 50
```

运行 `eidos --help` 查看所有命令；运行 `eidos <命令> --help` 查看某个命令的参数。

## 初始化智能体 Skill

CLI 已经内置 Eidos Skill，智能体配置不需要 Node.js、`npm` 或 `npx`：

```bash
# 安装到当前 Space / 项目。
eidos skills init

# 安装到当前用户，供所有项目使用。
eidos skills init --global
```

要初始化其他 Space，可使用 `eidos skills init --space <DIR>`。命令会写入标准的
`.agents/skills/eidos` 目录，可以安全重复执行；如果文件已有本地修改，必须显式传入
`--force` 才会更新。初始化后请新建一个智能体任务。

命令行工具只管理 Eidos File，不管理 Eidos Lite 的 Space 和本地历史。需要文件夹导航、
Space 历史或同步时，请使用 Eidos Lite。

面向智能体的工作流可继续阅读[安全自动化指南](/zh-cn/cli/automation-workflow/)，其中包含
Schema 意图命令、Runtime-backed Formula/Lookup、基于业务键的 `rows upsert`，以及混合
`rows mutate` 的原子批量操作。
