Eidos 不完整复制某一个扩展平台，而是组合三种成熟思路：

- [Pi extension](https://github.com/badlogic/pi-mono/blob/main/packages/coding-agent/docs/extensions.md)
  的单模块开发、project-local package、reload loop 和 semantic user interaction；
- [VS Code custom editor](https://code.visualstudio.com/api/extension-guides/custom-editors)
  的声明式 contribution、lazy provider activation、webview custom UI 和 document/view 分离；
- [Obsidian plugin](https://docs.obsidian.md/Plugins/Getting%20started/Build%20a%20plugin)
  与 [custom Bases view](https://docs.obsidian.md/plugins/guides/bases-view) 的轻量 View 开发体验、
  theme token 和 data-driven custom view。

安装体验可以像 Pi 一样直接，但 runtime 不继承 Pi 或 Obsidian 的 full-process trust model。从
GitHub 下载的代码始终需要经过 Eidos capability boundary。

## 三层 UI

```text
Manifest contribution
        │
        ├── host-rendered contribution
        │     commands, menus, settings, actions
        │
        ├── semantic UI request
        │     notice, select, confirm, progress
        │
        └── custom UI surface
              file editor, Base view, side panel
                     │
                     ▼
              sandboxed iframe
                     │ MessagePort
                     ▼
              capability gateway
```

### Host-rendered contribution

宿主已经拥有交互时，优先使用声明式数据。Eidos 负责渲染 menu、command palette entry、settings
control、toolbar action 和标准 list。扩展只提供 label、state 和 command handler，不替换宿主 chrome。

这样可以让 keyboard navigation、accessibility、theme、placement 和 context menu 在不同扩展间保持一致。

### Semantic UI

Worker code 可以请求一次宿主交互，而不决定具体 pixels：

```ts
const accepted = await context.window.confirm({
  title: "Complete task",
  message: "Mark this task as completed?",
})
```

同一个 intent 今天可以由 Desktop 渲染，未来也可以由其他 Eidos host 渲染。Semantic UI 可用于
non-visual command extension，不需要 UI entrypoint。

### Custom UI surface

只有 native contribution 无法表达产品时，才使用 custom surface，例如 visual file editor、interactive
Base view 或 domain-specific panel。UI entrypoint 运行在 sandboxed iframe 中，只获得 serializable
view state、theme token、localization helper 和专用 capability port。它不会获得 host React tree、
Electron bridge、SQLite connection、filesystem handle 或不受限制的 network access。

## UI entrypoint 不要求同时存在 Worker

如果所有行为都属于一个 surface，package 可以只有 `entrypoints.ui`。只有 command、agent tool 或
其他 non-visual handler 才需要 worker entrypoint。Discovery 和 **Reopen with** 都来自 Manifest，
不需要先激活任何 entrypoint。

对于 custom editor，Manifest contribution 的 `id` 同时也是 UI entrypoint 使用的 registration
key。这个设计遵循 VS Code provider model，避免引入第二个含义不清的 component identifier。

## Text file editor

文本编辑器使用宿主拥有的 document model：

```text
Space file
   │ open
   ▼
TextDocument { uri, version, text, dirty }
   │                         ▲
   │ snapshot/change        │ applyTextEdits(expectedVersion)
   ▼                         │
one or more sandboxed editor surfaces
```

Surface 不能直接保存整个文件，而是针对 expected version 提交 minimal edits。Eidos 负责 dirty
state、undo/redo、autosave、external-file conflict、Graft-visible write，以及 split view 之间的同步。

打开 Markdown Task Board 的完整流程是：

1. `fileEditors` 让 **Task Board** 出现在 **Reopen with**。
2. Eidos 打开一个 `TextDocument`，把 snapshot 发送给 UI surface。
3. 扩展解析 Markdown task list，渲染 progress、filter 和 grouped tasks。
4. 用户切换 task 时，扩展只为 checkbox marker 提交一条 versioned text edit。
5. Eidos 应用 edit、记录 undo state、autosave，并把新 version 广播给每个 view。

Editable binary format 需要未来的 custom-document contract。Readonly binary preview 可以更早交付，
因为它不拥有 save 或 undo state。

## Base view

Base view 接收宿主生成的 serializable query result 与 view configuration。扩展负责 render 并发出 typed
row/view action，不获得 raw SQLite handle。Eidos 持久化 view configuration，并在数据或配置变化时
通知 surface。

大结果集 view 必须支持 incremental update 与 virtualized rendering。宿主可以 suspend hidden surface，
再从 serialized state 重新创建。

## Lifecycle

每个 surface 都可 dispose，并绑定 package runtime generation。关闭 tab、禁用 package、修改 package
content 或 grant，或者替换 stale build，都会关闭 capability port 并 dispose surface。旧 generation
的迟到消息会得到 `RUNTIME_STALE`，不能修改当前数据。

## 首期交付边界

第一个可执行切片只实现 command、menu、read-only file capability 和宿主渲染的 semantic UI。
只有在 text-document contract 以及 save、undo、conflict、multi-view tests 完成后，custom
`fileEditors` 才能激活。这个顺序让 public Manifest 保持可扩展，同时避免把直接 `writeFile()` 的
捷径变成永久 API debt。
