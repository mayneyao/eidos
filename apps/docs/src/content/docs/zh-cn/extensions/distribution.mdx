GitHub 是 distribution source，不是 runtime dependency。Eidos 不会直接执行 mutable branch，
也不会在正常 activation 期间从网络下载 module。

## Repository 要求

Repository root 包含：

```text
extension.json
src/
assets/           optional
README.md
LICENSE
```

Version 1 package 使用 relative module 或可审查的 vendored source。Eidos 不安装任意 npm
dependency，也永远不会执行 install script 或 package-manager lifecycle hook。

当前开发者预览**只支持公开 GitHub repository**。Package 必须位于 repository root；暂不解析
monorepo subdirectory、private repository、GitHub token、Git submodule 或 Git LFS object。
发布者不能提交 `extension.lock.json`：安装快照时由 Eidos 创建并管理这个文件。

## 在 Desktop 中安装

1. 打开一个 file Space，进入 **Settings → Space → Extensions**；
2. 点击 **Install from GitHub**；
3. 输入 `owner/repository` 或完整 GitHub URL；也可以填写 branch、tag 或完整 commit，留空代表 `HEAD`；
4. 点击 **Prepare review**。Eidos 会把 ref 解析成 40 位 commit，在有资源上限的私有 staging 中下载，
   并验证完整文件树；
5. 审阅 immutable commit、changed files 和每项 permission change；
6. 点击 **Install reviewed source**；
7. 展开新安装的 package，分别信任精确源码、授权必要 capability，再启用它。

安装不会自动 activation。成功安装后 package 仍是 disabled 和 untrusted，所以仅仅粘贴 repository URL
永远不会执行下载的代码。

## 安装流程

```text
GitHub URL + requested ref
          │ resolve immutable commit
          ▼
download into private staging directory
          │ validate manifest, paths, compatibility, and files
          ▼
show identity + source + permissions + changed files
          │ user confirms
          ▼
atomically vendor source into .eidos/extensions/<id>/
          │ write extension.lock.json
          ▼
discover as installed, disabled, and untrusted
```

只有再完成 trust、permission 和 enable 流程，package 才能运行。

## Lock file

`extension.lock.json` 记录安装 provenance，不描述 package behavior：

```json
{
  "lockVersion": 1,
  "source": {
    "kind": "github",
    "repository": "https://github.com/example/hello-eidos",
    "requested": "refs/tags/v0.1.0",
    "commit": "0123456789abcdef0123456789abcdef01234567"
  },
  "contentDigest": "sha256:..."
}
```

Lock file 由 Eidos 管理，并且与 package source 一起进入版本管理。
每个 installed package 拥有自己的 lock file；version 1 不使用会让无关 package update 相互冲突的
Space-wide extension lock。
`contentDigest` 是从该 commit 复制时的 baseline。Local edit 会把 package 标记为 modified，
但不会让它无效。Update 会比较当前 digest 与 baseline，绝不静默覆盖 mismatch；runtime trust
使用根据当前 content 重新计算的 digest。

## 更新

首个版本只提供手动更新。Eidos 会解析新源码、展示 source diff 和 permission diff，并且拒绝静默
覆盖用户在本地修改的扩展文件。新 digest 得到 trust 后才能激活。

在已安装的 GitHub package 上点击 **Check update**，可以重新解析 lock file 记录的 branch、tag 或
commit。应用审阅过的更新时会原子替换 package。如果任意 installed source 与 lock baseline 不同，
更新按钮会被禁用；请先提交或另存本地修改，不要依赖 Eidos 自动 merge。

## 卸载

卸载会停止 active runtime，并且把 installed source 作为普通的、Graft 可见的删除处理。Build cache
异步清理；local setting 和 secret reference 进入可恢复的 grace period，需要另一个明确操作才能永久删除。

Invalid package 也可以直接从诊断行移除。移除使用内联二次确认，不要求先运行或修复无效代码。

## 未来的社区目录

社区目录可以是经过审查的 extension ID 与 GitHub repository 索引，不需要变成另一套 package hosting system。
