Eidos 扩展是安装在 Space 内的自包含 package。Manifest 会在任何扩展代码执行之前告诉 Eidos
这个 package 提供哪些 contribution。运行时代码获得的是 capability-based SDK，而不是 Electron、
Node.js、SQLite 或宿主文件系统的原始访问权限。

## 扩展可以提供什么

| Contribution    | 用途                                              | 首期交付     |
| --------------- | ------------------------------------------------- | ------------ |
| `commands`      | 可放入菜单和命令面板的具名操作                    | 是           |
| `menus`         | 把 command 放入上下文菜单                         | 是           |
| `panels`        | 在编辑区域 tab 中运行的 sandboxed 独立 UI         | Experimental |
| `fileEditors`   | 根据文件 pattern 或 media type 选择编辑器和预览器 | Experimental |
| `folderViews`   | 面向文件夹的专用视图                              | 后续         |
| `baseViews`     | 由宿主分页供数的只读 Base grid 替代视图           | Experimental |
| `agentTools`    | 可由 Agent 调用且经过权限检查的工具               | 后续         |
| `configuration` | 由宿主渲染并具有明确存储 scope 的设置             | 后续         |

旧版 `FileAction`、`DocAction` 和 `TableAction` 会被归一化为 command 与 menu placement，
不再拥有单独的 package runtime。

## 开发路径

1. 使用[开发工具](/zh-cn/extensions/tooling/)创建并校验 package。
2. 开发可执行的 [Markdown Task Board](/zh-cn/extensions/quickstart/)。
3. 理解[package 结构](/zh-cn/extensions/anatomy/)。
4. 在 [Manifest](/zh-cn/extensions/manifest/) 中声明 contribution。
5. 正确处理[生命周期与激活](/zh-cn/extensions/lifecycle/)。
6. 阅读[安全模型](/zh-cn/extensions/security/)。
7. 准备通过 [GitHub 分发](/zh-cn/extensions/distribution/) package。

开发自定义界面前，请先阅读 [UI 扩展架构](/zh-cn/extensions/architecture/)和可执行的
[surface protocol contract](/zh-cn/reference/extension-surface-protocol/)。

## 核心不变量

安装和执行是两个不同决定。Package 可以已经存在于 Space 中并且被 Graft 看到，但仍然可能因为
untrusted、不兼容、缺少权限或者构建失败而保持禁用。
