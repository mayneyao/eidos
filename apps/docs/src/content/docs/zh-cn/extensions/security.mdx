扩展边界必须能够处理从 GitHub 下载的代码。Source review 可以提高信任，但它不是运行时安全边界。

## 三个独立决定

1. **信任 content digest。** 用户接受已经审查的、完整 installed package tree。
2. **授予 capability。** 用户批准 Manifest 请求的 file pattern、network origin、setting scope
   或其他宿主操作。
3. **启用 package。** 用户决定这个 package 是否可以在当前安装中激活。

修改除宿主管理的 `extension.lock.json` 外的任何已安装 package 文件，或修改请求的权限，都会让
对应 trust decision 失效。通过 Graft 回滚到完全相同且曾被信任的 digest 时，可以复用原来的
trust record。

## Runtime isolation

- 当前 Desktop 预览中，非视觉代码运行在每个 package 独立且按需创建的 Web Worker 中；Worker
  位于使用独立内存 session 的隐藏 sandboxed Electron renderer 内。
- 固定 preload 不暴露任何 API，只负责把 main process 创建的一条独立 `MessagePort` 传给
  sandboxed host page，再转交给 Worker。
- 扩展 UI 目前只支持宿主拥有的 notice、confirm 和 select 控件。Sandboxed iframe 文档 surface
  属于后续 UI 阶段，当前尚未启用。
- 宿主会为每次请求验证 package identity、当前 grant、path scope、参数和 runtime generation。
- 扩展永远不会得到原始 `DataSpace`、SQL connection、Electron bridge、filesystem handle 或完整 secret collection。

## 文件权限

Pattern 相对于 Space root。`.eidos` 和 `.graft` 内部路径默认拒绝访问，除非专用 host capability
明确处理。允许读取 `notes/**` 不代表允许写入，也不代表可以访问相邻目录。
预览版 `readText` 只接受不超过 512 KiB 的文本文件；binary 或被截断的预览会默认拒绝。

## 网络权限

当前预览尚未启用 network capability。在扩展代码求值前，ambient `fetch`、XHR、WebSocket、
EventSource、嵌套 Worker、cache 和 IndexedDB 都会被阻断；独立 Electron session 也会拒绝所有
出站请求。未来的 network capability 将只允许显式 HTTPS origin，并重新验证 redirect，且不会
继承 Eidos 的 cookie 或认证状态。

## Secret

扩展保存的是用户管理 secret 的引用。宿主只在具体操作需要时解析值；secret 不会被复制到 package
源码、Graft 历史、日志或宽泛的初始化 payload 中。

## 恢复

Eidos 必须能够在禁用全部第三方 package 的状态下启动。扩展 crash 或 hang 时，宿主可以终止它，
而不需要关闭 Space 或破坏其他扩展 runtime。
