---
title: 使用 Docker 部署 Graft
---

在自己的 Linux 服务器上运行 Eidos Lite 同步服务。按照下面的步骤完成部署后，
你会得到一个可以在 Lite 中连接的 HTTPS 地址。

**本地磁盘**配置最简单；也可以选择 **Cloudflare R2**，将对象存入私有桶。
两种方式都需要在服务器上保留持久化磁盘空间。

## 开始前准备

准备一台 Linux AMD64 或 ARM64 服务器，并确保：

- 已安装 [Docker Engine 和 Compose v2](https://docs.docker.com/engine/install/)。
- 已安装 Bash、curl 和 OpenSSL。以下命令在 Bash 中执行，当前用户需要有运行 Docker 的权限。
- 有一个域名，例如 `sync.example.com`，DNS 已指向服务器。
- 80 和 443 端口允许外部访问，宿主机上已[安装 Caddy 系统服务](https://caddyserver.com/docs/install)。

将下文的 `sync.example.com` 全部替换为你的域名。

## 1. 下载部署文件

为本次安装新建一个私有目录：

```bash
mkdir -m 700 ~/graft-sync
cd ~/graft-sync
curl -fL --retry 3 -o compose.yaml \
  https://github.com/eidos-space/graft/releases/download/graft-docker-v0.1.1/compose.yaml
```

该文件使用公开的 [Graft Docker 0.1.1 镜像](https://github.com/eidos-space/graft/releases/tag/graft-docker-v0.1.1)，
通过摘要固定镜像内容。不需要登录 GitHub、下载源码或自行构建。
后续所有 Compose 命令都在这个目录中运行。

## 2. 创建服务器访问密钥

仅在首次安装时执行：

```bash
mkdir -m 700 secrets
(umask 077; openssl rand -hex 32 > secrets/access-key)
chmod 444 secrets/access-key
```

将密钥保存到密码管理器。它可以访问**这台服务器上的所有 Space**，
与用于加密 Space 的同步密码是两回事。

私有目录保护宿主机上的密钥；文件本身需要允许容器内的普通用户读取。
已有安装不要重复执行生成命令，否则会替换原来的密钥。

## 3. 选择存储方式

启动服务器之前，完成以下**其中一种**配置。

### 选项 A：本地磁盘

创建 `.env`，填写公开访问地址：

```bash
cat > .env <<'EOF'
GRAFT_PUBLIC_ORIGIN=https://sync.example.com
EOF
```

Docker 会创建持久化数据卷。接着执行第 4 步即可。

### 选项 B：Cloudflare R2

1. 在 Cloudflare 账户中创建一个私有 R2 存储桶。
2. 从存储桶配置中复制 **S3 API 端点**。
3. [创建 R2 S3 凭据](https://developers.cloudflare.com/r2/api/tokens/)，选择 **Object Read & Write（对象读写）** 权限，限定到这个桶。保存 **Access Key ID** 和 **Secret Access Key**。

这里需要 S3 凭据，而不是通用 Cloudflare API Token。
桶不需要公开访问地址。如果桶有数据管辖区限制，使用该桶配置中显示的端点。

下载额外的 Compose 文件：

```bash
curl -fL --retry 3 -o compose.s3.yaml \
  https://github.com/eidos-space/graft/releases/download/graft-docker-v0.1.1/compose.s3.yaml
```

按提示分别粘贴凭据。输入不会显示，也不会进入命令历史：

```bash
read -r -s -p 'R2 Access Key ID: ' graft_s3_key_id; printf '\n'
(umask 077; printf '%s' "$graft_s3_key_id" > secrets/s3-access-key-id)
unset graft_s3_key_id
read -r -s -p 'R2 Secret Access Key: ' graft_s3_secret; printf '\n'
(umask 077; printf '%s' "$graft_s3_secret" > secrets/s3-secret-access-key)
unset graft_s3_secret
chmod 444 secrets/s3-access-key-id secrets/s3-secret-access-key
```

创建 `.env`，替换域名、端点和桶名：

```bash
cat > .env <<'EOF'
COMPOSE_FILE=compose.yaml:compose.s3.yaml
GRAFT_PUBLIC_ORIGIN=https://sync.example.com
GRAFT_S3_ENDPOINT=https://YOUR_ACCOUNT_ID.r2.cloudflarestorage.com
GRAFT_S3_REGION=auto
GRAFT_S3_BUCKET=your-private-bucket
GRAFT_S3_PREFIX=graft/
GRAFT_S3_FORCE_PATH_STYLE=true
EOF
```

R2 的[区域填写 `auto`](https://developers.cloudflare.com/r2/api/s3/api/)。
使用专用桶，或为本次安装保留一个独占前缀，前缀以 `/` 结尾。
`COMPOSE_FILE` 会让后续命令自动加载两个 Compose 文件。

R2 保存对象数据，但 Docker 数据卷仍要保存元数据和未完成的上传。
服务器磁盘需要容纳上传分片，以及每个正在完成上传的对象的一份组装副本。

## 4. 启动服务器

```bash
docker compose config --quiet
docker compose pull
docker compose up -d
docker compose ps
curl --fail --show-error --silent --retry 10 --retry-all-errors --retry-delay 2 \
  http://127.0.0.1:8787/healthz
```

最后一条命令应返回成功的健康检查响应。如果失败，先查看日志：

```bash
docker compose logs --tail=100 graft
```

容器只监听 `127.0.0.1:8787`，接下来通过 Caddy 提供公开访问。

## 5. 配置 HTTPS

在宿主机的 `/etc/caddy/Caddyfile` 中添加以下配置，保留已有站点：

```text
sync.example.com {
    reverse_proxy 127.0.0.1:8787
}
```

检查配置并重新加载 Caddy：

```bash
sudo caddy validate --config /etc/caddy/Caddyfile
sudo systemctl reload caddy
curl -fsS https://sync.example.com/healthz
```

公开健康检查成功后再连接 Lite。如果证书签发失败，检查 DNS，
以及 80 和 443 端口是否能到达 Caddy。

如果使用其他代理，请允许至少 64 MiB 的请求体和至少 120 秒的传输时间，
原样转发路径和授权请求头，并关闭 API 缓存。
如果代理也运行在容器中，需要使用共享 Docker 网络，将上游设为 `graft:8787`，
而不是照搬上面的本机地址配置。

## 6. 连接 Lite

在服务器上查看访问密钥：

```bash
cat secrets/access-key
```

按照 [连接自托管服务器](/zh-cn/recipes/sync-custom-server/) 在 Lite 中操作，
服务器地址填写 `https://sync.example.com`，粘贴访问密钥。
同时妥善保存 Space 同步密码，服务器访问密钥不能代替它。

连接后，添加一条记录和一个小附件。在另一台电脑上下载 Space，打开记录和附件，
再从第二台电脑修改记录，确认第一台能收到更新。
这样可以确认整套配置能够同步，而不只是健康检查正常。

首次连接会确认上传的数据已保存。使用这个版本的服务器时，
确认过程不需要 Lite 把完整上传内容再下载回来，但服务器仍会读取已存储的对象。
旧版服务器可能需要完整下载。如果确认失败，保留本地 Space，
解决提示的问题后重试。

## 日常维护

### 停止和重新启动

在 `~/graft-sync` 目录执行：

```bash
docker compose stop
docker compose start
```

保留部署目录及其 Docker 数据卷。
**除非确实要删除服务器的本地数据，否则不要执行 `docker compose down -v`。**
每个数据卷只运行一个 Graft 实例。

### 备份和升级

先暂停同步、停止容器，再进行备份：

- **本地存储：**备份完整的 `/data` 数据卷。
- **R2 或其他 S3 存储：**在服务器停止期间，同时备份 `/data` 和对应的桶内对象。只备份其中一份无法完整恢复。
- 安全保存 Compose 文件、`.env` 和访问密钥的备份。Space 同步密码另行保存。

备份后重新启动容器。先在独立的空数据卷中测试恢复，
通过客户端下载确认内容完整，再依赖这份备份。
R2 本身不等于备份：删除对象会移除它的当前副本。

升级前先备份。将新版发布的 Compose 文件下载到临时目录，与现有文件比较，
更新镜像引用和必要设置，保留你的 `.env`、密钥及数据卷。然后执行：

```bash
docker compose pull
docker compose up -d
curl -fsS https://sync.example.com/healthz
```

在 Lite 中确认同步正常后，再考虑清理旧镜像和备份。

### 其他 S3 服务和存储迁移

修改存储模式、端点、桶名或前缀，**不会**自动迁移数据。
已有服务需要更换存储时，请用全新存储部署另一台服务，
然后在 Lite 中使用**切换服务器**。

首次安装使用其他 S3 服务时，沿用选项 B，填写服务商提供的 HTTPS 端点、
区域和凭据。例如 Backblaze B2：从桶详情复制端点和区域，创建限定到该桶的
[应用密钥](https://www.backblaze.com/docs/cloud-storage-application-keys)，
将 `keyID` 保存到 `secrets/s3-access-key-id`，
将 `applicationKey` 保存到 `secrets/s3-secret-access-key`。

凭据需要允许桶访问、对象读写删除和分片上传，包括取消未完成的上传。
启用版本控制的桶还需要允许删除对象版本。对象锁定和保留规则可能阻止删除。
不要给本次安装前缀中的有效对象设置自动过期规则。
存储、请求和传输仍会产生服务商费用。

本版本已实测本地存储、MinIO 和 Cloudflare R2。
B2 配置使用其 S3 API，但没有进行真实 B2 存储桶实测。

## 常见问题

| 现象                 | 排查方法                                                                                     |
| -------------------- | -------------------------------------------------------------------------------------------- |
| Compose 提示缺少变量 | 检查部署目录中的 `.env`；R2 需要填写选项 B 的全部字段。                                      |
| 本机健康检查失败     | 运行 `docker compose ps` 和 `docker compose logs --tail=100 graft`，检查密钥权限和磁盘空间。 |
| 公开健康检查失败     | 检查 DNS、防火墙端口和 Caddy 配置。                                                          |
| Lite 提示授权失败    | 填写服务器访问密钥，而不是 Space 同步密码或 R2 凭据。                                        |
| R2 传输失败          | 检查 S3 端点、桶名，以及限定到该桶的对象读写凭据。                                           |
