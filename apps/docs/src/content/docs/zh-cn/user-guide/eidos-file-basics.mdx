Eidos File 是一份有明确数据模型的 SQLite 文档。它可以像普通文件一样复制，也可以用熟悉的
SQLite 工具检查；只要通过兼容的 Eidos Runtime 编辑，在不同应用中都保持同样的含义。

## 理解文件的组成

| 部分   | 含义                                                         |
| ------ | ------------------------------------------------------------ |
| 数据表 | 一组带类型的记录，例如任务或书籍                             |
| 字段   | 每条记录共有的属性，例如状态、截止日期或评分                 |
| 记录   | 带稳定 identity 的一行数据                                   |
| 视图   | 数据表的一种保存展示方式，包含可见字段、筛选、排序与视图属性 |

文件还保存稳定 ID、revision 元数据、关系、派生字段定义和附件引用。应用依靠这些信息，在重命名、
切换视图和跨设备使用时保持数据含义。

Grid、Gallery 与 Kanban 都是同一组记录的视图。在一个视图中修改记录，结果会出现在其他
视图中，不会产生另一份数据副本。

## 选择打开方式

| Host       | 适合的场景                            |
| ---------- | ------------------------------------- |
| Web Editor | 无需安装应用，创建或打开一份文件      |
| CLI Serve  | 用浏览器界面编辑一份本地文件          |
| Eidos Lite | 管理文件夹、本地历史，以及可选的 Sync |
| Eidos CLI  | 脚本、校验、可重复导入和自动化        |

所有 Host 使用同一套 File 与 Runtime 语义；差别主要在文件访问、附件获取、保存流程和可选历史服务。

## 创建第一张表

在 Web Editor 中选择**新建**或模板。使用 CLI 时，可以在创建文件时同时创建第一张表：

```bash
eidos create tasks.eidos \
  --table Tasks \
  --label-field Title \
  --fields '[{"name":"Title","type":"text"},{"name":"Priority","type":"select"}]'
```

每张表都有一个记录标题字段（Record Label Field）。Eidos 在记录详情、卡片和关系中用它标识
记录。应该选择人能识别的字段，例如**标题**、**姓名**或**订单号**，而不是内部状态或时间戳。

接下来在编辑器中：

1. 添加真正需要查询或展示的属性字段。
2. 新建一条记录，先填写记录标题。
3. 为受控状态建立单选目录，例如“待处理、进行中、已完成”。
4. 需要不同筛选、排序或布局时，再建立第二个视图。

完整字段说明见[数据表与字段](/zh-cn/user-guide/tables-and-fields/)。

对于单选字段，可以在字段属性中选择一个可选的**默认选项**。只有创建操作没有提供该字段时，
Eidos 才会自动分配默认值；显式清空会抑制默认值。已有记录和 CSV 导入记录不会被回填。
重命名该选项会保留默认关系，删除该选项则会清除默认值。

## 录入和展开记录

Grid 最适合连续录入。长文本、关系或附件在单元格中空间不足时，可以展开记录。记录详情、卡片
与 Grid 编辑的是同一行数据，不存在需要稍后合并的“卡片副本”。

关系字段保存目标记录的稳定 ID，并显示目标表当前的记录标题。标题改名只改变展示，不会改变关系。
关联、附件、多单元格粘贴和撤销行为见[记录与编辑](/zh-cn/user-guide/records-and-editing/)。

## 建立聚焦的视图

视图会保存筛选、排序、可见字段和布局。搜索是临时的；清空搜索框后会回到已保存的视图。

日期和日期时间筛选提供早于/晚于、包含边界、起止区间和相对条件。相对条件把过去、未来或
本期与日、周、月、年组合；保存在视图中后仍保持相对语义，不会变成固定日期。

筛选组、多级排序、可见字段、Grid/Gallery/Kanban 布局，以及“本月更新的未完成工作”等示例，
见[视图、搜索、筛选与排序](/zh-cn/user-guide/views-and-querying/)。

## 确认文件已经保存

编辑界面是共享的，但保存方式由 Host 决定：

- Web 直接文件模式只有在浏览器授权并完成冲突检查后才会写入。
- Web 导入副本模式需要**另存为**或下载副本。
- CLI Serve 和成功的 CLI 修改会写入打开的路径。
- Eidos Lite 写入本地文件；本地历史与 Sync 是另外两层。

关闭前应检查保存状态，确认哪一份副本已经持久化。完整矩阵见[数据位置与安全](/zh-cn/user-guide/data-safety/)。

## 第一份文件检查清单

- 表名只描述一种事物。
- 记录标题能让每一行被人识别。
- 受控状态使用单选或多选，而不是拼写不一致的文本。
- 不关心时刻时用日期，需要时刻时用日期时间。
- 用保存视图表达工作流，不把临时搜索误认为视图。
- 重要文件在当前工作副本之外还有普通备份。
