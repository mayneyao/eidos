Space 是设备上的文件夹。移动或备份工作时，
把文件和它们引用的附件一起保留。

## 顺着文件找数据

<FileMap lang="zh-cn" />

`.eidos` 文件保存表、字段、记录、公式和视图定义。
File 字段保存引用，可以指向独立文件，也可以包含受支持的内联数据。
不要假定所有附件都在数据库里。

在 Lite 的 Markdown 笔记中粘贴图片时，图片保存在笔记旁边的 `assets/`
文件夹，笔记通过相对路径引用它。

## 保存只是恢复工作的一部分

<DataChoices lang="zh-cn" />

版本和 Sync 的用途不同于独立备份。
磁盘损坏可能同时丢失本地历史，Sync 也可能把不需要的改动带到另一台设备。

## 做一份能够恢复的备份

1. 完成编辑，确认改动已保存。
2. 关闭 Space，停止其他会写入这些文件的程序。
3. 把整个 Space 复制到独立存储。需要保留本地历史时，也要包含隐藏的历史文件。
4. 打开一份单独恢复的副本，检查重要记录、笔记和附件。

如果备份工具要复制正在使用的数据库，请采用该工具说明的一致性快照方式。
不要假定只复制一个仍在写入的 SQLite 数据库，就能包含全部已提交内容。

文件元数据管理把自定义值保存在物理文件的属性中。
确认备份工具会保留这些属性。只复制 `files.eidos` 不会备份它们。
详见[文件元数据的可移植性](/zh-cn/user-guide/file-metadata/)。

## 文件被锁定时

关闭另一个正在写入该文件的编辑器，再重试。
不要通过删除锁文件或数据库附属文件来强制打开。
详见[故障排查](/zh-cn/user-guide/troubleshooting/)。
