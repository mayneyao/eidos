## 数据保存在哪里

| 使用方式                | 持久数据                            | 写入方式                                           |
| ----------------------- | ----------------------------------- | -------------------------------------------------- |
| Web Editor 直接文件模式 | 你选择的 `.eidos` 文件              | 浏览器授权并完成冲突检查后，**保存**写回文件       |
| Web Editor 导入副本模式 | 你另存或下载的文件                  | 浏览器内工作副本不是原文件，需使用**另存为**或下载 |
| CLI 命令                | 传给 `eidos` 的路径                 | 命令成功后，修改会直接写入该文件                   |
| CLI Serve               | 传给 `eidos serve` 的路径           | 编辑器中每次成功的修改都会写入文件                 |
| Eidos Lite              | 普通 Space 文件夹中的 `.eidos` 文件 | 修改写入本地文件，版本历史单独保存                 |

查询和编辑 Eidos File 都不需要上传文件。

## 正确理解保存状态

单元格提交成功表示 Runtime 接受了修改；修改是否已经到达原文件，仍取决于上表中的 Host。
浏览器工作副本可以完整有效并且可编辑，但仍需要**另存为**，才会在浏览器存储之外持久存在。

如果原文件被当前编辑器之外的程序改变，应停止并显式选择重新加载、覆盖或另存为。不能因为
某个窗口最后仍可见，就假设它拥有最新的完整状态。

## 安全习惯

1. 对重要 `.eidos` 文件或整个 Space 做普通文件备份。
2. 不要用多个应用同时编辑同一文件。出现占用、锁定或外部变更提示时，先关闭另一个应用。
3. 关闭浏览器标签页前检查标题栏保存状态。
4. 无法获得写权限，或原文件已被外部修改时，使用**另存为**。
5. 自动化写入完成后执行完整校验。

```bash
eidos important.eidos validate --level full
```

## 备份并测试恢复

有效备份应包含 `.eidos` 文件，以及你希望保留的所有普通 Space asset。没有 writer 正在提交时
复制，然后打开副本或运行校验。一次也没有恢复验证过的备份流程，只是一个假设。

CSV 导出用于交换，不是备份。它不会保留 identity、视图定义、关系、公式、选项元数据和完整
File entry。

## 附件安全

文件字段保存便携的 entry 元数据。引用的字节可能是 inline、相对 Host asset 区域，或来自明确
授权的 HTTPS resource。使用独立 relative asset 时，只备份数据库文件并不充分，应备份整个
Space 布局。

能预览附件不等于内容已经安全或通过校验。打开不受信任文档时，应保持与 Eidos 外部相同的谨慎。

## Raw SQLite 访问

可以使用 SQLite 工具检查 Eidos File，但不要直接执行 SQL 写入。直接写入可能绕过版本、字段值、
关系、派生字段和校验规则。修改文件请使用 Runtime 或 CLI。
