Eidos Lite 采用彻底的**本地优先（Local-First）**架构。打开一个 Space，实际上就是直接打开你电脑上的一个普通文件夹。所有的编辑操作都会直接写入本地文件。

本地使用不需要登录，绝不会在后台私自上传你的任何文件。

---

## 1. 你的数据保存在哪里？

### `.eidos` 文件（结构化数据库）
`.eidos` 文件包含你创建的所有表格、自定义列、数据行、计算公式和视图排版。它是一个自包含的独立文件，可以像普通文件一样随时复制、移动或发送。

### 附件与图片文件的存放位置
为了防止庞大的二进制附件把数据库撑大导致卡顿，附件采用更加稳妥的独立存放方案：
- **普通附件与文件**：图片、PDF、视频等大文件作为独立实体存放在 Space 文件夹中，`.eidos` 文件仅记录它们的相对位置引用。
- **Markdown 笔记中的图片**：在 Eidos Lite 的 `.md` 笔记中粘贴图片时，系统会自动将图片保存到当前文档同级目录下的 `assets/` 文件夹中（例如 `assets/image.png`），并插入便携的相对路径。这保证了即使离开 Eidos Lite，用任何其他 Markdown 编辑器打开也能正常显示图片！

:::tip[移动与分享工作区的黄金法则]
如果你整理的文件中包含许多附件与图片，**请直接移动或复制整个 Space 文件夹**，而不是只拷贝单个 `.eidos` 文件，以确保所有相对引用的图片完好无损。
:::

## 2. 如何安全备份你的 Space

由于 Space 本质上就是一个普通文件夹，物理备份极其简单：

1. 确认当前文件已完成输入。
2. 在系统文件管理器（Finder 或资源管理器）中，直接右键复制整个 Space 文件夹。
3. 将副本粘贴到你的移动固态硬盘（SSD）、U 盘、NAS 或电脑的备份目录（如 macOS 的 Time Machine）中。
4. 定期备份可以有效防止硬件损坏或误删文件带来的不可逆损失。

## 3. 时光机版本、多端同步与物理备份的区别

很多用户容易混淆这三种机制，它们各自承担着不同的职责：

| 机制 | 解决的痛点 | 是否能替代物理备份？ |
| :--- | :--- | :--- |
| **本地版本（Versions）** | 在单台电脑上记录历史节点，方便随时回滚误操作。 | **否**。版本与源文件存放在同一块磁盘上，磁盘损坏依然会同时丢失。 |
| **多端同步（Sync）** | 在多台不同电脑（如 Mac 和 Windows）之间无缝传递最新内容。 | **否**。同步会把删除和修改实时传给其他设备，不能防误删。 |
| **物理备份（Backup）** | 将整个 Space 复制到另一块独立硬盘或存储设备中。 | **终极安全屏障**。这是应对电脑丢失或磁盘物理损坏的唯一保障。 |

---

## 4. 避免多程序写入冲突

`.eidos` 采用高性能文件锁保护机制。请尽量避免同时在两个不同的软件（例如同时在两个独立的窗口或第三方 SQLite 管理工具）中同时修改同一个 `.eidos` 文件。如果系统提示“文件被锁定或已被外部修改”，只需关闭其他占用程序后重新打开即可。
