Space 是你本地设备上的普通文件夹。
在移动或备份数据时，请始终将文件与引用的附件一同保存。

## 顺着文件查找数据

<FileMap lang="zh-cn" />

`.eidos` 文件存储表格、字段、记录、公式与已保存视图。
File 附件字段存储文件引用。
这些引用指向磁盘上的独立文件，或存储受支持的内联数据。
不要假定所有外部附件都内嵌在 SQLite 数据库内部。

在 Eidos Lite 的 Markdown 笔记中粘贴图片时，图片保存在笔记旁的 `assets/` 文件夹中。
笔记通过相对路径链接到这些图片。

## 保存只是数据安全的一部分

<DataChoices lang="zh-cn" />

版本历史与同步服务服务于不同的场景，不能替代独立的离线备份。
磁盘硬件故障可能导致工作文件与本地历史一同丢失。
云端同步也可能将意外的误修改同步到其他设备。

## 制作可完整恢复的备份

1. 完成日常编辑，确认改动均已写入文件。
2. 关闭当前 Space，停止其他向该文件夹写入数据的外部程序。
3. 将整个 Space 文件夹复制到独立的外部存储介质。如需保留本地历史，请包含隐藏的 `.graft` 目录。
4. 打开一份恢复后的副本进行检验，检查重要记录、笔记与附件。

如果使用第三方热备份工具复制正在使用的数据库，请遵循该工具的一致性快照方案。
不要假定仅复制一个处于写入状态的 SQLite 文件就能获得完整一致的数据。

文件元数据管理将自定义值保存在物理文件的扩展属性中。
请检查你的备份工具是否支持保留扩展属性。
仅复制 `files.eidos` 不会备份写在物理文件上的元数据。
详见[文件元数据管理说明](/zh-cn/user-guide/file-metadata/)。

## 当文件被其他程序锁定时

关闭另一个正在占用该文件的编辑器或外部进程，然后重试。
不要强行删除锁文件或数据库附加文件来强制打开。
详见[故障排查指南](/zh-cn/user-guide/troubleshooting/)。
