**文件元数据管理**将文件夹中的文件作为表格记录呈现。
你可以添加 Status、Rating 或 Tags 等字段来整理文件。

配置信息存储在 `files.eidos` 中。
自定义属性值直接保存在物理文件自身的扩展属性中。
这是两个不同的存储位置：仅复制配置文件不会复制打标结果。

---

## 1. 快速上手

在需要管理的文件夹中操作：

1. **新建文件**：在 Eidos Lite 侧边栏选择新建文件（快捷键 `Cmd/Ctrl + N`），文件类型选择 **Eidos**。
2. **开启开关**：勾选底部的 **文件元数据管理** 开关，文件名自动固定为 `files.eidos`，点击**创建**。每个目录只创建一份配置，已有同名文件不会被覆盖。
3. **开始打标**：打开表格，点击列头右侧的 **+（添加列）** 按钮。输入属性名称（如“审核状态”、“星级”或“标签”），即可像操作普通表格一样直接为文件录入元数据。

---

## 文件夹浏览与元数据配置

右键文件夹选择 **显示此文件夹**，可将其作为侧边栏的根目录。
目录树上方的面包屑路径支持随时返回上级。
搜索栏旁的 **文件排序** 支持按名称、修改时间与文件类型升序或降序排列。
文件夹始终靠前显示。
系统会跨会话保存你的排序偏好。

子目录新建 `files.eidos` 时，会自动继承最近父目录配置的自定义字段、类型、选项、视图设置与属性存储键。
这在创建时完成单次继承复制。
后续修改父级配置不会覆盖已有子级配置。
继承不复制物理文件。
共享命名空间与存储键的配置读取同一物理文件上的属性。

## 2. 日常工作流与文件安全

- **原文件零拷贝**：所有物理文件保留在本地磁盘原位。编辑自定义字段仅修改文件扩展属性，不修改文件内容。
- **自动感知磁盘变动**：在操作系统中添加、重命名或删除文件时，表格会实时感知并更新，无需手动刷新。
- **打开实体文件**：只读的 `file` 单元格提供快速打开操作。本地大文件（包括高清视频）直接通过系统默认应用打开，无需读入编辑器内存。

在文件行的右键菜单中选择**在侧边栏打开**，即可保留表格，在右侧查看文件。预览沿用你配置的文件打开方式，包括自定义 File View。拖动预览标题栏可移动整个桌面窗口。

菜单打开后，按住 macOS 的 **Option** 或 Windows/Linux 的 **Alt** 显示拖动手柄。拖动菜单项可调整顺序，也可以选择**恢复默认顺序**。菜单仅在排序时扩宽，默认不预留手柄空白。顺序保存在本地应用偏好中，跨表格共用。

CSV 可以在同一个 `.eidos` 文件中导入为另一张普通表格。
普通表格之间支持 Relation 关联。
基于文件系统驱动的 `files` 表格不能作为关联关系的源或目标。
URL 字段正常受支持。

## 3. 管理范围与扫描边界

**开启元数据管理的 `.eidos` 文件会扫描其所在文件夹及所有子目录。**

它不会向上扫描父目录。
它不会跟随符号链接。
它会自动跳过被忽略的项目。
在子目录新建的表格仅扫描该子目录及其后代。

## 4. 多级嵌套目录与属性共享

大型项目通常包含多层子文件夹。
父文件夹与子文件夹各自可以创建 `files.eidos`：

<FileTree>

- Creative-Project/
  - **files.eidos** 包含所有子目录文件
  - Project-Plan.pdf
  - Budget.xlsx
  - Visual-Assets/
    - **files.eidos** 独立管理子目录
    - Hero-Poster.png
    - Brand-Logo.svg
    - Illustration.jpg
  - References/
    - Competitive-Review.md
    - Moodboard.png

</FileTree>

### 独立的布局与视图配置

父文件夹与子文件夹下的 `.eidos` 是相互独立的文档：
两者的表格排版、视图模式、过滤规则与排序设置互不干扰。
子目录中的文件均可被父级表格统一汇总呈现。

### 物理文件上的底层元数据共享

自定义属性直接写入物理文件的扩展属性：

- **字段名即存储键**：新字段直接使用字段名作为底层存储键。使用相同键的不同表格可以共享属性值。
- **不支持字段重命名**：元数据字段名不支持重命名。已有带有 `field_…` 键的字段继续保留原映射。打开文件不会覆盖外部属性。

### 重要注意事项

1. **修改直接作用于物理文件**：共享存储键的表格会感知彼此的修改。
2. **移动与重命名文件**：同一文件系统内的文件重命名会保留扩展属性。跨磁盘或网络传输是否保留取决于具体工具。
3. **“删除字段”与“清空单元格”的区别**：
   - **删除列（字段）**：删除该列并从受影响的物理文件上清除该扩展属性。这会影响共享该属性的其他表格。
   - **清空单元格**：仅从特定单个物理文件上清除该项属性值。
4. **属性便携性**：
   - macOS 和 Linux 使用扩展属性（xattr），Windows 使用备用数据流（ADS）。底层文件系统必须支持此特性。
   - 通过不支持扩展属性的第三方网络工具传输或拷入 FAT32 格式磁盘时，附加的扩展属性可能会丢失。
5. **事务边界**：进程运行期间支持基于内存日志的撤销与保存点回滚。该日志保存在内存中，不提供防崩溃原子性。

## 5. 系统内置只读字段

系统自动提取以下底层物理属性（只读）：

| 字段 | 类型 | 说明 |
| :--- | :--- | :--- |
| `name` | 文本 | 物理文件名（如 `Photo.jpg`） |
| `path` | 文本 | 相对路径（作为记录标题与唯一标识） |
| `extension` | 文本 / 标签 | 文件后缀名（如 `jpg`、`mp4`、`pdf`） |
| `size` | 文本 / 整数 | 文件大小（自动格式化为 KB、MB 或 GB） |
| `mimetype` | 文本 | 媒体类型（如 `image/jpeg`、`video/mp4`） |
| `file` | 附件引用 | 本地文件实体引用，用于缩略图与快速打开预览 |
