版本功能会记录整个 Space 的状态，包括其中的 `.eidos` 文件和普通文件。适合在完成一组改动后保存一个明确的节点，例如“整理完客户资料”或“发布前版本”。

版本保存在本地，不需要登录。

## 开启版本功能

1. 打开一个 Space。
2. 点击窗口右上角的**版本**按钮（时钟图标）。
3. 点击 **Enable versioning**。

Eidos Lite 会把 Space 当前的状态保存为第一个版本。以后再次打开版本面板，就会看到 **Changes** 和 **History** 两个页面。

## 排除不需要版本管理的文件

如果生成文件、缓存、密钥或其他仅需保留在本地的内容不应进入版本管理，可以在 Space 中添加 `.gitignore` 或 `.graftignore` 文件。Eidos Lite 会读取 Space 根目录和各级子目录中的这些文件。匹配规则且尚未被跟踪的文件不会出现在 **Changes** 中，也不会加入之后保存的版本。

两种文件都使用 Git 的忽略规则语法。希望规则同时作用于 Git 时使用 `.gitignore`；只希望影响 Eidos Lite 版本管理时使用 `.graftignore`。同一目录中的两个文件都匹配某个路径时，`.graftignore` 规则优先；子目录中的规则优先于从父目录继承的规则。

例如：

```text
node_modules/
*.tmp
private/
```

忽略规则不会删除本地文件。如果某个路径在添加匹配规则之前已经被跟踪，它仍会继续进入版本管理，已有历史也会保留。

## 保存一个版本

1. 完成一组改动后，打开**版本**面板。
2. 在 **Changes** 中检查发生变化的文件。
3. 在 **Version note** 中写一句说明，例如“补充八月账单”。这一步可以省略。
4. 点击 **Save version**。

保存后，当前改动会出现在 **History** 中。

:::tip
如果希望 Eidos Lite 在工作停止一段时间后自动保存版本，可以在**设置 → Spaces → Automatic versions** 中开启自动版本。
:::

## 查看以前的改动

1. 打开**版本**面板，切换到 **History**。
2. 点击一个版本，查看当时修改了哪些文件。
3. 继续点击文件，可以查看支持的文本或表格差异。

查看历史不会改变当前文件。

## 恢复旧版本

恢复会让**整个 Space**回到所选版本，不只是当前打开的文件。

1. 先在 **Changes** 中确认没有未保存的改动。若有，请先保存一个版本。
2. 打开 **History**，选择要恢复的版本。
3. 点击 **Restore this version**。
4. 确认后点击 **Restore Space**。

恢复完成后，Eidos Lite 会再保存一个版本来记录这次恢复。需要时，你仍然可以回到恢复前的状态。

## 版本不能替代备份

版本历史和 Space 位于同一台电脑上。如果设备或磁盘损坏，两者都可能丢失。重要内容仍应按照[数据、附件与备份](/zh-cn/user-guide/data-safety/)中的方式备份整个 Space。
