浏览器恢复、本地历史、同步和备份保护的是不同状态下的数据。

| 机制                          | 防范的问题                            | 不能替代                         |
| ----------------------------- | ------------------------------------- | -------------------------------- |
| 浏览器恢复副本                | 关闭或刷新页面时丢失未保存的 Web 编辑 | 保存文件或普通备份               |
| 系统废纸篓                    | 从 Eidos Lite Explorer 删除文件       | 版本历史或异地备份               |
| Graft 本地历史                | 回到命名状态、查看受支持的变更        | 独立备份设备或远端               |
| Eidos Sync（Private Preview） | 在本地 Space 与认证远端之间保持连续性 | 本地所有权或显式冲突处理         |
| 普通备份                      | 设备丢失、损坏或错误的历史操作        | Runtime 校验与经过测试的恢复流程 |

## Web 恢复

浏览器支持时，Web Editor 会在浏览器私有存储中保存可恢复工作。恢复后，应立即保存或下载
持久文件。清理站点数据可能会删除浏览器恢复内容。

## Lite 历史与同步

Eidos Lite 使用 Graft 提供本地 checkpoint 和记录级历史。本地工作不需要账号。Sync
是仅限邀请的 Private Preview，并明确显示登录、授权、拉取、检查、校验和推送状态。同步失败
不会影响本地文件，应用也会显示相应的恢复操作。

加入 waitlist 不会自动获得 Sync 权限。申请获批前，Lite 保持完全本地运行，不会 provision
或连接远端。无论是否拥有 Sync 权限，都应保留普通文件备份。

已获批并连接的 Space 可以增量 Pull 干净的 fast-forward 更新，在关闭期间安全取消、
重新打开常驻 Eidos File handle，并再次重试。如果 Local 与 Hosted 历史发生分叉，
Lite 会在物化前停止，通过显式恢复副本流程保留双方；不会 force push，也不会擅自选择
merge 赢家。

## 理解 Sync 阶段

连接或 clone Space 是多阶段操作：检查访问权限、准备本地或远端计划、传输对象、校验结果文件，
最后确定连接状态。只有知道传输总量后，字节进度、速度和预估时间才有意义，因此 planning 可能
先于总量出现。

普通 Sync 中：

- **Fetch** 获取并下载 Hosted 历史与对象。
- **Analyze** 比较稳定的 Local 与 Hosted commit。
- **Pull** 把干净的 Hosted 前进应用到本地 Space。
- 只有双方历史都有新工作且无法 clean fast-forward 时才进入 **Merge**。
- **Push** 在校验后发布最终本地 commit。

一个 pack request 可以包含多个 commit 与对象；commit 数量不意味着每个 commit 都完整下载一次。

## Sync 需要处理时

1. 保留本地 Space 和 recovery copy；不要通过删除任一份来清状态。
2. 打开 Sync 详情，确认失败阶段和可重试操作。
3. Pull 前先提交或有意放弃无关 working change。
4. Merge 没有 unresolved conflict 时，应自动完成而不展示冲突解决界面。如果零冲突界面仍然
   停留，应记录状态并重试，不要虚构冲突选择。
5. Pull 成功后，让 Lite 重新打开常驻 Eidos File session，以便前端 cache 失效后再继续编辑。

如果重试持续失败，请保留 Lite 版本、操作系统、Space identifier、阶段、error record 和相关
JSONL 日志。Sync 停止时，本地文件仍应可用。
