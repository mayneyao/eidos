This guide builds **Markdown Task Counter**, a small but useful extension for
people who keep tasks in Markdown notes.

## The user scenario

Suppose `projects/website.md` contains:

```md
# Website launch

- [x] Choose a domain
- [ ] Finish the landing page
- [ ] Invite beta users
```

After installing the extension, the user can:

1. find `website.md` in the Files sidebar;
2. right-click the file;
3. select **Count Markdown tasks**;
4. see `projects/website.md: 2 open, 1 completed` in an Eidos notice.

The extension never modifies the note and never uses the network. It requests
read access to Markdown files only.

## What happens when the command runs

```text
User right-clicks website.md
          │
          ▼
Eidos matches `resourceExtname == .md`
          │
          ▼
User chooses “Count Markdown tasks”
          │ lazy activation
          ▼
Extension worker reads this file through context.space.files
          │
          ▼
Extension counts `[ ]` and `[x]` task-list items
          │
          ▼
Eidos displays a host notice with the result
```

This flow demonstrates the three parts every command extension needs:

- a **manifest contribution** so Eidos can discover the command;
- an **activation handler** containing the behavior;
- a **permission declaration** covering the host operation.

## Step 1: Create the package

Create the following directory outside your production Space while developing:

```text
markdown-task-counter/
├── extension.json
└── src/
    └── extension.ts
```

The complete version used by these docs is available at
[`apps/docs/examples/markdown-task-counter`](https://github.com/mayneyao/eidos/tree/dev/apps/docs/examples/markdown-task-counter).

## Step 2: Describe the extension

Create `extension.json`:

```json
{
  "$schema": "https://docs.eidos.space/schemas/extension-manifest.schema.json",
  "manifestVersion": 1,
  "publisher": "example",
  "name": "markdown-task-counter",
  "displayName": "Markdown Task Counter",
  "description": "Count open and completed tasks in a Markdown file.",
  "version": "0.1.0",
  "engines": { "eidos": ">=0.34.0" },
  "entrypoints": { "worker": "src/extension.ts" },
  "contributes": {
    "commands": [
      {
        "id": "example.markdown-task-counter.count-tasks",
        "title": "Count Markdown tasks"
      }
    ],
    "menus": {
      "files/context": [
        {
          "command": "example.markdown-task-counter.count-tasks",
          "when": "resourceExtname == .md"
        }
      ]
    }
  },
  "permissions": {
    "files": { "read": ["**/*.md"], "write": [] },
    "network": []
  }
}
```

The important lines are:

| Manifest value              | Why it exists                                                       |
| --------------------------- | ------------------------------------------------------------------- |
| `publisher` + `name`        | Derives the stable package ID `example.markdown-task-counter`.      |
| `commands`                  | Makes the command searchable without running extension code.        |
| `files/context`             | Places the command in the Files sidebar context menu.               |
| `when`                      | Hides the command for folders, images, and non-Markdown files.      |
| `files.read`                | Lets the host explain and enforce exactly what the worker may read. |
| empty `write` and `network` | Proves the extension does not need these capabilities.              |

## Step 3: Implement the command

Create `src/extension.ts`:

```ts
import type { ExtensionContext } from "@eidos.space/extension-sdk"

export function activate(context: ExtensionContext) {
  context.subscriptions.add(
    context.commands.register(
      "example.markdown-task-counter.count-tasks",
      async (resource) => {
        const text = await context.space.files.readText(resource.path)
        const open = text.match(/^\s*[-*]\s+\[ \]/gim)?.length ?? 0
        const completed = text.match(/^\s*[-*]\s+\[[xX]\]/gim)?.length ?? 0

        context.window.showNotice(
          `${resource.path}: ${open} open, ${completed} completed`
        )
      }
    )
  )
}
```

`activate()` does not run when Eidos starts. The first invocation of the command
creates the package worker. `context.subscriptions` ensures the command handler
is removed when the extension is disabled, updated, or stopped.

The regular expressions intentionally count only Markdown task-list items at
the start of a line. Text such as ``Use `[ ]` as a marker`` is not counted.

## Step 4: Validate the package

From an Eidos repository checkout, run:

```bash
pnpm --filter docs check:examples
```

Expected output:

```text
Validated example.markdown-task-counter
```

The current check verifies that:

- the complete manifest matches the published version 1 JSON Schema;
- command IDs belong to the package;
- menu items refer to declared commands;
- entrypoints are relative paths that exist inside the package.

The installer will perform these checks before any source is trusted or run.

## Step 5: Install and approve it

The target runtime flow is:

1. Open **Settings → Extensions**.
2. Select **Install from local folder** during development, or paste the GitHub
   repository URL for a published package.
3. Review the resolved source, package ID, changed files, and requested
   permission: **Read Markdown files in this Space**.
4. Select **Install**. Eidos copies an immutable source snapshot into
   `.eidos/extensions/example.markdown-task-counter/`.
5. Select **Trust and enable**. Installation alone never runs the package.

These UI actions are not available in stable builds yet. They are described
here so the implementation and its acceptance tests have a concrete target.

## Step 6: Use the extension

Once the runtime is available and the extension is enabled:

1. Create or open a Markdown file containing `- [ ]` and `- [x]` tasks.
2. In the **Files** sidebar, right-click that file.
3. Confirm that **Count Markdown tasks** appears. It should not appear on a
   folder, image, `.base`, or other non-Markdown file.
4. Select the command.
5. Confirm the notice reports the expected open and completed counts.

Try these edge cases:

| File content               | Expected result       |
| -------------------------- | --------------------- |
| No task-list items         | `0 open, 0 completed` |
| `* [ ] Task`               | Counted as open       |
| `- [X] Task`               | Counted as completed  |
| ``Text containing `[ ]` `` | Not counted           |

## Step 7: Change and debug it

During local development, changing any installed package file other than the
host-managed `extension.lock.json` creates a new content digest. Eidos stops the
old worker and requires trust for the new digest before reload.
The Extension Manager should show manifest, build, activation, and permission
errors against this package instead of silently retaining the previous bundle.

| Symptom            | Check                                                                      |
| ------------------ | -------------------------------------------------------------------------- |
| Command is missing | Confirm the file ends in `.md` and the menu command ID matches `commands`. |
| Permission error   | Confirm `files.read` includes the selected relative path.                  |
| Activation error   | Open the package diagnostics and inspect `src/extension.ts`.               |
| Counts are wrong   | Add the failing Markdown line to a test before changing the parser.        |
