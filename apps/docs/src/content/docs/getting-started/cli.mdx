The standalone `eidos` CLI works directly with `.eidos` files.
It does not require Eidos Lite or a background service.

## 1. Install the CLI

<Tabs syncKey="cli-install">
  <TabItem label="macOS / Linux">

```bash
curl -fsSL https://download.eidos.space/cli/install.sh | sh
```

  </TabItem>
  <TabItem label="Windows PowerShell">

```powershell
irm https://download.eidos.space/cli/install.ps1 | iex
```

  </TabItem>
</Tabs>

Restart your terminal if `eidos` is not on your `PATH`.
Run `eidos --help` to check the installation.

## 2. Optional: initialize the Agent Skill

The CLI includes an AI agent skill for coding assistants.
You do not need Node.js or `npx`:

```bash
# Current project
eidos self skill init

# Global configuration for all projects
eidos self skill init --global
```

Use `eidos self skill init --space <DIR>` to target another folder.
The tool will not overwrite modified skill files without `--force`.

## 3. Create a file with a table

```bash
eidos file new example.eidos \
  --table Tasks \
  --label-field Title \
  --fields '[{"name":"Title","type":"text"},{"name":"Status","type":"select"}]'
```

The CLI makes this initial table the default table.
It creates a Grid view for the table.
Fields accept empty values by default.

## 4. Open the local editor

```bash
eidos serve example.eidos --open
```

The server listens on `127.0.0.1` by default.
It opens the shared editor UI in your browser.
It writes committed changes directly to `example.eidos`.
To access the editor from another local device, run `eidos serve example.eidos --lan`.
Press <kbd>Ctrl</kbd> + <kbd>C</kbd> to stop the server.

<Aside type="tip" title="Check the file">

```bash
eidos file validate example.eidos --level full
```

</Aside>

Continue with the [CLI and automation guide](/cli/).
To publish a read-only web copy, follow [Publishing with the CLI](/cli/publish/).
To keep an editor connected to local files, use [`eidos serve`](/cli/serve/).
